# DBA Trainer

[English version](README.md)

DBA Trainer — полностью офлайн-приложение для обучения администрированию баз данных и программированию. Общая логика написана на Rust и используется одновременно терминальным интерфейсом и Android-приложением.

Сейчас основной учебный трек посвящён PostgreSQL DBA. Структура репозитория позволяет позже добавлять отдельные направления SQL, Rust, Python и другие курсы.

## Текущая версия

Текущая версия приложения: **0.2.0**.

Готовые сборки при публикации хранятся непосредственно в репозитории в `releases/<version>/`:

```text
releases/
└── v0.2.0/
    ├── dba-trainer-android-v0.2.0.apk
    ├── dba-trainer-tui-linux-x86_64-v0.2.0.tar.gz
    └── dba-trainer-tui-windows-x86_64-v0.2.0.zip
```

Android-файл — обычный устанавливаемый APK. Для Linux и Windows публикуются терминальные бинарники; отдельный desktop GUI/инсталлятор не требуется.

## Возможности

- полностью офлайн-работа;
- не требуется учётная запись, backend или сетевой сервис;
- хранение состояния в SQLite;
- тесты по отдельным темам;
- общий тест в пределах верхнеуровневого курса, например `DBA-1`, `DBA-2` и будущих направлений;
- режимы 20, 50 или все доступные вопросы;
- вопросы с одним и несколькими правильными ответами;
- после ответа показываются результат, объяснение и источник;
- продолжение незавершённого теста;
- явная отмена активной сессии;
- общая статистика, статистика по курсам, темам и режимам;
- очистка статистики;
- интерфейс на английском и русском;
- язык по умолчанию — английский;
- выбранный язык запоминается отдельно в Android и TUI;
- выбор локализованного учебного контента во время выполнения с fallback при отсутствии перевода.

## Языки учебного контента

Контент хранится отдельно по locale:

```text
course-content/
└── dba-1/
    └── 01-tools-install/
        ├── en/
        │   ├── topic.json
        │   └── questions.json
        └── ru/
            ├── topic.json
            └── questions.json
```

Каталог языка может быть пустым. Перевод считается доступным только когда в каталоге присутствуют одновременно `topic.json` и `questions.json`.

При запуске приложение пытается использовать выбранный язык контента. Если такого перевода нет, загрузчик выбирает доступный fallback. Поэтому английский интерфейс может временно показывать русский банк вопросов, пока `en/` не заполнен.

Переводы должны сохранять одинаковую логическую идентичность: код курса, slug темы, ключи вопросов, ключи ответов, тип вопроса, правильность ответов и идентичность источников. Благодаря этому статистика и сохранённые сессии не ломаются при смене языка.

Подробности: [course-content/README.md](course-content/README.md).

## Архитектура

```text
Android / Jetpack Compose        TUI / Ratatui
            │                         │
            └──────────┬──────────────┘
                       │
                  application
                       │
        ┌──────────────┼──────────────┐
        │              │              │
      domain         content     storage-sqlite
                                      │
                                    SQLite

Android
  └── Kotlin / Compose
       └── UniFFI
            └── mobile-ffi
                 └── общая Rust-логика
```

UI не выполняет SQL самостоятельно. Бизнес-правила находятся в Rust и переиспользуются обоими интерфейсами.

## Запуск и сборка TUI

Для разработки:

```bash
cargo run -p dba-trainer-tui
```

Оптимизированная сборка под текущую платформу:

```bash
cargo build --release -p dba-trainer-tui
```

Готовый бинарник появляется в `target/release/`.

## Сборка Android

Нужны Android SDK, Android NDK, Rust targets для Android и `cargo-ndk`.

Сборка Rust-библиотек:

```bash
cargo ndk \
  -t arm64-v8a \
  -t x86_64 \
  -o apps/android/app/src/main/jniLibs \
  build \
  --release \
  -p dba-trainer-mobile-ffi
```

После изменения экспортируемого Rust FFI нужно заново сгенерировать Kotlin bindings:

```bash
cargo run \
  -p uniffi-bindgen \
  -- \
  generate \
  target/aarch64-linux-android/release/libdba_trainer_mobile_ffi.so \
  --language kotlin \
  --out-dir apps/android/app/src/main/java \
  --no-format
```

Debug APK:

```bash
cd apps/android
./gradlew assembleDebug
```

Публичный APK собирается и подписывается локально постоянным project keystore. Сам keystore и пароли нельзя коммитить в Git.

## Выпуск версии

GitHub Actions и repository secrets для релизов не требуются. Готовые файлы собираются локально, проверяются и копируются в `releases/<version>/`, после чего создаются release commit и Git tag.

Перед релизом:

```bash
cargo fmt --check
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets
```

После этого нужно проверить Android-сборку и установить итоговый APK на устройство.

## Приватность

DBA Trainer рассчитан на офлайн-использование. Прогресс и статистика хранятся локально в SQLite. Учётная запись и удалённый backend не требуются.
