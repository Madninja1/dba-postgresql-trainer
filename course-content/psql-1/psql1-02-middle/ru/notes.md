# Middle — уверенный psql

## 1. Тема

На Initial-уровне psql был интерактивным клиентом: подключиться, выполнить SQL, посмотреть объекты. На Middle-уровне важно понять **состояние самого клиента** — query buffer, переменные, формат вывода, ввод/вывод файлов и условную логику скриптов.

Модель уровня:

```text
ввод / файл / переменные
          ↓
       psql client
          ↓
     query buffer
          ↓
        \g / ;
          ↓
 PostgreSQL server
          ↓
результат → формат / файл / pipe / переменные
```

Это уже не просто «набор удобных команд». psql становится небольшим скриптовым окружением вокруг SQL.

---

# 2. Механизм

## Query buffer: запрос до отправки серверу

Пока SQL ещё не отправлен серверу, psql хранит его текст в **query buffer**.

Например, после ввода:

```sql
SELECT
    pid,
    usename
FROM pg_stat_activity
```

без завершающей `;` текст остаётся в буфере.

Основные операции:

```text
\p                 показать buffer
\r                 очистить buffer
\g                 выполнить buffer
\gx                выполнить с expanded output
\w file.sql        записать buffer в файл
\w |command        передать buffer программе
```

### `\p` — посмотреть

```text
\p
```

Печатает содержимое текущего query buffer. Если буфер пуст, psql показывает последний выполненный запрос.

### `\r` — сбросить

```text
\r
```

Очищает query buffer. Это полезно, если набранный запрос оказался неправильным и его проще отбросить.

### `\g` — выполнить

```text
\g
```

Отправляет текущий query buffer серверу. Без аргументов по смыслу близка к завершающей `;`.

Если буфер пуст, `\g` повторно выполняет предыдущий запрос.

`\g` умеет одноразово перенаправить результат:

```text
\g result.txt
\g |some_command
```

В отличие от `\o`, это перенаправление относится только к текущему выполнению.

Также `\g` может временно изменить параметры форматирования только для одного запроса:

```text
\g (format=aligned tuples_only=off expanded=on)
```

### `\gx` — `\g` + expanded output

```text
\gx
```

Работает как `\g`, но для текущего выполнения принудительно включает expanded output.

То есть:

```text
\g     выполнить как есть
\gx    выполнить и показать результат вертикально
```

### `\w` — сохранить текст запроса

```text
\w query.sql
```

Записывает **сам query buffer**, а не результат запроса.

Можно передать его программе:

```text
\w |command
```

Это отличается от `\o`, который перенаправляет **результаты** запросов.

## Expanded output — `\x`

В обычном режиме строка результата выводится горизонтально:

```text
id | name | created_at | ...
```

Для широких результатов это неудобно. Команда:

```text
\x
```

переключает expanded mode, в котором одна строка отображается вертикально как набор `поле | значение`.

Можно явно задать состояние:

```text
\x on
\x off
\x auto
```

`\x` эквивалентна настройке `\pset expanded`.

При запуске psql тот же режим включает:

```bash
psql -x
```

---

## Время выполнения — `\timing`

```text
\timing on
```

включает отображение времени выполнения каждого SQL-оператора.

```text
\timing off
```

отключает его.

Без аргумента состояние переключается:

```text
\timing
```

`\timing` не меняет timezone и не запускает `EXPLAIN`: это именно клиентский показ времени выполнения команды.

## Форматы вывода и CLI-эквиваленты

Параметры вывода настраиваются через:

```text
\pset parameter value
```

Несколько часто используемых режимов имеют короткие команды и CLI-ключи.

### Unaligned — `-A`

```bash
psql -A
```

переключает вывод в `unaligned` mode. То же можно сделать:

```text
\pset format unaligned
```

В этом режиме значения отделяются активным разделителем полей и вывод удобнее обрабатывать другими программами.

### CSV — `--csv`

```bash
psql --csv
```

включает CSV-формат. Эквивалент:

```text
\pset format csv
```

### Expanded — `-x`

```bash
psql -x
```

эквивалентно включению `\x` / `\pset expanded`.

### Tuples only — `-t`

```bash
psql -t
```

убирает заголовки столбцов и результирующую строку с количеством записей. Внутри psql:

```text
\t
```

или:

```text
\pset tuples_only
```

Запомнить различие:

```text
-A       формат unaligned
--csv    формат CSV
-x       expanded output
-t       только данные без служебного оформления
-U       пользователь, к форматированию не относится
```

## Перенаправление результатов — `\o`

```text
\o result.txt
```

направляет результаты последующих запросов в файл.

Вернуть обычный вывод:

```text
\o
```

Можно перенаправлять вывод в программу:

```text
\o |command
```

Важно отличать:

```text
\w file     сохраняет текст query buffer
\o file     перенаправляет результаты запросов
\g file     направляет результат одного выполнения
```

---

## Выполнение файлов — `\i`

```text
\i script.sql
```

или:

```text
\include script.sql
```

читает команды из файла и обрабатывает их так, как если бы они вводились в psql.

Для скриптов с вложенными файлами существует также `\ir` / `\include_relative`. В интерактивном режиме она похожа на `\i`, но при вызове из файла относительный путь вычисляется относительно каталога самого включающего скрипта.

Разница уровней:

```text
psql -f file.sql    выбрать файл при запуске psql
\i file.sql         включить файл из уже работающего psql/скрипта
```

## `\copy` и серверный `COPY`

Это одна из важнейших практических разниц psql.

### Серверный `COPY`

SQL-команда вида:

```sql
COPY users TO '/var/lib/postgresql/users.csv' CSV;
```

работает с файлом со стороны **серверного процесса PostgreSQL**.

Следовательно, путь относится к файловой системе сервера, а доступ определяется серверными привилегиями.

### psql `\copy`

```text
\copy users TO 'users.csv' CSV HEADER
```

psql организует передачу данных между сервером и **локальной файловой системой клиента**.

Модель:

```text
COPY ... '/server/path'
        ↓
файл открывает PostgreSQL server

\copy ... 'local/path'
        ↓
файл открывает psql client
        ↓
данные передаются между клиентом и сервером
```

Следствия `\copy`:

- файл читает/пишет psql;
- используются права локального пользователя ОС, запустившего psql;
- для доступа к локальному файлу не требуются серверные superuser file privileges;
- данные **проходят между клиентом и сервером**, поэтому утверждение «данные не передаются по сети» неверно.

Именно поэтому `\copy` часто удобнее с рабочего компьютера DBA, а серверный `COPY` может быть эффективнее для больших объёмов, если серверу непосредственно доступен нужный файл.

## Переменные psql

Переменная psql — пара **имя/значение**. Значением может быть строка любой длины, поддерживаемой psql.

Создание или изменение:

```text
\set foo bar
```

Проверить значение:

```text
\echo :foo
```

Удалить обычную переменную:

```text
\unset foo
```

Показать все установленные переменные:

```text
\set
```

Если вызвать `\set` только с именем:

```text
\set foo
```

переменная получает пустую строку (для некоторых специальных управляющих переменных действуют дополнительные правила).

Имена переменных могут содержать буквы, цифры и подчёркивания и чувствительны к регистру. Они не обязаны начинаться с `PG_`.

Не путайте:

```text
\set NAME value    переменная psql
SET name = value   SQL-команда настройки PostgreSQL
```

---

## Подстановка переменной — `:name`

После:

```text
\set foo 42
```

запись:

```sql
SELECT :foo;
```

подставляет текст значения переменной.

Для первого понимания достаточно трёх форм:

```text
:name       подставить значение как текст
:'name'     корректно оформить как SQL-литерал
:"name"     корректно оформить как SQL-идентификатор
```

Например:

```text
\set table_name users
SELECT * FROM :"table_name";
```

и:

```text
\set login alice
SELECT * FROM users WHERE name = :'login';
```

Без кавычек `:name` — **буквальная текстовая подстановка**. Безопасность этих форм и проверку существования переменной подробно разберём на Strong-уровне.

---

## `\gset`: результат запроса → переменные

`\gset` связывает SQL и переменные psql.

Пример:

```sql
SELECT current_database() AS db,
       current_user AS usr
\gset
```

После этого:

```text
\echo :db :usr
```

выведет значения столбцов.

Критическое правило: запрос для `\gset` должен вернуть **ровно одну строку**.

```text
0 строк       → переменные не меняются
1 строка      → столбцы записываются в переменные
>1 строки     → переменные не меняются
```

Каждый столбец становится отдельной переменной с именем столбца.

Можно добавить префикс:

```sql
SELECT current_database() AS db, current_user AS usr
\gset conn_
```

получим:

```text
:conn_db
:conn_usr
```

Если значение столбца равно SQL `NULL`, соответствующая psql-переменная **удаляется**, а не получает текст `NULL`.

---

## `\watch`: повторять запрос

`\watch` повторяет текущий query buffer. Если буфер пуст, используется последний переданный запрос.

Например:

```sql
SELECT now(), count(*) FROM pg_stat_activity;
\watch 5
```

запускает запрос повторно с указанным интервалом.

Если интервал не указан, значение по умолчанию — **2 секунды**.

Современная форма также позволяет ограничить число выполнений:

```text
\watch interval=1 count=10
```

`\watch` не ограничена только `SELECT` без параметров: она выполняет текущий запрос так же, как `\g`, повторяя его до достижения `count`, ошибки или прерывания.

## Условия в psql-скриптах

psql имеет собственные условные блоки:

```text
\if expression
    ...
\elif expression
    ...
\else
    ...
\endif
```

Пример вместе с `\gset`:

```sql
SELECT EXISTS (
    SELECT 1
    FROM pg_roles
    WHERE rolname = 'app'
) AS role_exists
\gset

\if :role_exists
    \echo 'role exists'
\else
    \echo 'role does not exist'
\endif
```

Это логика **psql client**, а не `CASE` в SQL и не `IF` PL/pgSQL.

Поддерживаемые части блока:

```text
\if
\elif
\else
\endif
```

Команды вроде `\switch` в этом механизме нет.

## Шаблоны объектных команд `\d*`

Команды вроде:

```text
\dt
\di
\df
\dn
```

принимают шаблоны имён.

### `*` — любое количество символов

```text
\dt app*
```

ищет таблицы, имя которых начинается с `app`.

### `?` — один символ

```text
\dt log_?
```

`?` соответствует одному символу.

### `schema.object`

Точка разделяет шаблон схемы и объекта:

```text
\dt public.*
```

### `*.*` — независимо от текущей видимости

Без шаблона команды `\d*` обычно показывают объекты, видимые через текущий `search_path`.

```text
\dt *.*
```

позволяет искать по всем схемам, то есть не ограничиваться текущей видимостью объекта.

### Регистр и двойные кавычки

Как и SQL-идентификаторы, некавыченные части шаблона обычно приводятся к нижнему регистру.

Двойные кавычки сохраняют регистр и делают специальные символы шаблона внутри кавычек обычными символами. То есть `*` и `?` внутри двойных кавычек уже не wildcard.

---

## `\d+`: расширенное описание

Знак `+` у многих объектных метакоманд добавляет детали.

Например:

```text
\d users
\d+ users
```

Обе команды описывают объект, но `\d+` показывает дополнительную информацию. Для разных объектов это могут быть комментарии, размер, права, свойства хранения или другие специфичные поля.

`+` **не означает**, что psql автоматически добавит все системные объекты. Для системных объектов у ряда команд используется отдельный модификатор `S` или явный шаблон.

# 3. Важные детали

## Не путайте «текст запроса» и «результат запроса»

```text
\p      показать текст buffer
\r      удалить текст buffer
\w      сохранить текст buffer

\g      выполнить buffer
\o      изменить канал результатов
\g file выполнить один раз и записать результат
```

Это разные сущности: query buffer существует до выполнения, результат появляется после ответа сервера.

---

## `\copy` определяется местом, где открывается файл

Самая полезная проверка:

```text
кто открывает файл?
```

Если сервер PostgreSQL — это SQL `COPY` с серверным файлом.

Если процесс psql — это `\copy`.

---

## `\gset` — не «выбрать одну из строк»

psql не берёт автоматически первую или последнюю строку. Контракт строгий:

```text
ровно одна строка результата
```

Если SQL потенциально возвращает много строк, сначала сформируйте запрос так, чтобы он гарантированно выдавал одну.

# Что запомнить

Query buffer:

```text
\p          показать
\r          очистить
\g          выполнить
\gx         выполнить в expanded mode
\w file     сохранить текст запроса
```

Вывод:

```text
\x          expanded output
\timing     время SQL-команд
\o file     результаты в файл

-A          unaligned
--csv       CSV
-x          expanded
-t          tuples only
```

Файлы:

```text
\i file.sql           выполнить psql-скрипт
COPY ... server path  файл открывает сервер
\copy ... local path  файл открывает клиент psql
```

Переменные:

```text
\set name value   установить
\unset name       удалить
\set              показать все
:name             обычная подстановка
:'name'           SQL-литерал
:"name"            SQL-идентификатор
```

SQL → переменные:

```text
query
  ↓
ровно 1 строка
  ↓
\gset [prefix]
  ↓
каждый столбец → отдельная psql-переменная
NULL            → переменная удаляется
```

Автоматизация:

```text
\watch                 повторять query buffer
интервал по умолчанию   2 секунды
count=N                 ограничить число выполнений

\if / \elif / \else / \endif
```

Шаблоны:

```text
*       любое количество символов
?       один символ
schema.object
*.*     искать независимо от видимости search_path
"..."   сохраняет регистр и отключает wildcard внутри кавычек
```
