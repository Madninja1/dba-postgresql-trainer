# Strong — продвинутый psql

## 1. Тема

Тема посвящена терминальному клиенту `psql`: подключению к PostgreSQL, выполнению SQL, метакомандам, переменным, форматированию и автоматизации работы клиента.

## 2. Механизм

Этот уровень — надёжные скрипты, коды завершения, безопасная интерполяция и продвинутые метакоманды.

### ON_ERROR_STOP

По умолчанию psql в скрипте может продолжить выполнение после SQL-ошибки. Переменная `ON_ERROR_STOP` меняет это поведение:

```text
\set ON_ERROR_STOP on
```

После ошибки psql прекращает обработку текущего скрипта.

Из командной строки:

```bash
psql -v ON_ERROR_STOP=1 -f deploy.sql
```

### --single-transaction / -1

```bash
psql -1 -v ON_ERROR_STOP=1 -f migration.sql
```

`-1` выполняет все `-c`/`-f` в одной транзакции: перед первым действием выполняется `BEGIN`, после последнего — `COMMIT`. Если при `ON_ERROR_STOP` произошла ошибка, вместо фиксации выполняется `ROLLBACK`.

Это не подходит, если скрипт сам выполняет несовместимое управление транзакциями или содержит команды, которые нельзя выполнять внутри транзакционного блока.

### Коды завершения

Для неинтерактивного использования важны exit codes psql:

- `0` — нормальное завершение;
- `1` — критическая ошибка самого psql;
- `2` — потеря/ошибка соединения в неинтерактивном режиме;
- `3` — ошибка скрипта при включённом `ON_ERROR_STOP`.

Это позволяет shell/CI корректно определять результат выполнения.

### Безопасная интерполяция

Формы переменных:

```text
:name       обычная подстановка
:'name'     SQL-литерал
:"name"     SQL-идентификатор
:{?name}    проверка, определена ли переменная
```

Для значений данных обычно нужна форма `:'name'`, а для имён таблиц/столбцов — `:"name"`.

### \gexec

`\gexec` выполняет запрос, затем воспринимает каждую непустую ячейку его результата как SQL-команду и выполняет её.

Пример генерации DDL:

```sql
SELECT format('ANALYZE %I.%I;', schemaname, tablename)
FROM pg_tables
WHERE schemaname = 'public'
\gexec
```

Это мощный инструмент, поэтому данные, из которых генерируется SQL, должны быть доверенными или корректно экранированными.

### \bind

`\bind` задаёт значения параметров `$1`, `$2` для **следующего** выполнения запроса и использует расширенный протокол PostgreSQL.

```text
INSERT INTO t VALUES ($1, $2)
\bind 'first' 'second'
\g
```

Действие относится только к следующему выполнению.

### \errverbose

После ошибки `\errverbose` показывает максимально подробное сообщение последней серверной ошибки, включая поля, которые могли быть скрыты обычным уровнем verbosity.

### ECHO_HIDDEN

`ECHO_HIDDEN=on` показывает SQL-запросы, которые psql генерирует внутри некоторых метакоманд (`\d` и подобных). Это полезно для изучения системных каталогов и диагностики.

### FETCH_COUNT

При `FETCH_COUNT > 0` psql получает результат порциями, используя курсор, вместо загрузки всего набора сразу. Это снижает пиковое потребление памяти при больших результатах.

### AUTOCOMMIT

При включённом `AUTOCOMMIT` каждая команда вне явного блока транзакции автоматически фиксируется. При выключенном psql самостоятельно начинает транзакцию перед командой, когда требуется, и пользователь должен явно выполнить `COMMIT` или `ROLLBACK`.

### Повторение и автоматизация

`\watch` можно применять и на продвинутом уровне для непрерывного мониторинга. Объектные шаблоны `\d*` позволяют делать точечную диагностику, а `ECHO_HIDDEN` помогает увидеть, какие каталоги стоят за метакомандами.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### Параметры

- **-1 / --single-transaction.** Оборачивает обработку всех -c/-f в одну транзакцию. psql выполняет BEGIN перед первым -c/-f и COMMIT после последнего; с ON_ERROR_STOP ошибка приводит к ROLLBACK.
- **-1 вместе с ON_ERROR_STOP.** -1 работает с одним или несколькими -c/-f. Документация отдельно предупреждает про явные transaction-control statements внутри скрипта.
- **Транзакционное поведение -c.** Одна строка -c передаётся серверу как один запрос. Документация `-c` отдельно описывает транзакционное поведение строки из нескольких SQL-команд.

### Код завершения

- **Код 3.** Документация кодов завершения выделяет код 3 для ошибки скрипта при ON_ERROR_STOP.
- **0, 1, 2, 3.** 0 — нормальное завершение. Раздел «Код завершения» документирует эти четыре значения.

### Переменные

- **ON_ERROR_STOP.** Останавливает обработку скрипта при ошибке вместо обычного продолжения. ON_ERROR_STOP меняет поведение psql при ошибках скрипта и влияет на exit code.
- **ECHO_HIDDEN.** Перед метакомандой, обращающейся к БД, показывать нижележащий SQL-запрос. ECHO_HIDDEN помогает изучать SQL, который psql генерирует для backslash-команд.
- **FETCH_COUNT.** Результаты SELECT извлекаются и отображаются порциями заданного размера. FETCH_COUNT ограничивает память клиента, отображая результат группами строк.
- **AUTOCOMMIT.** on является значением по умолчанию. Раздел специальных переменных описывает поведение AUTOCOMMIT и потерю незафиксированных изменений при выходе.

### Метакоманды

- **\gexec.** Выполняет каждое непустое поле результата запроса как SQL-команду. `\gexec` сначала выполняет query buffer, затем воспринимает поля результата как SQL для выполнения.
- **\bind.** Задаёт параметры для следующего выполнения запроса и использует extended query protocol. `\bind` задаёт значения `$1` и т. п. для следующего выполнения запроса.
- **\errverbose.** Повторить последнее серверное сообщение об ошибке с максимальной детализацией. `\errverbose` повторяет последнюю серверную ошибку как при VERBOSITY=verbose и SHOW_CONTEXT=always.
- **Поведение \gexec.** NULL-поля результата игнорируются. `\gexec` передаёт поля результата серверу буквально как SQL-команды.
- **Поведение \gset.** Запрос должен вернуть ровно одну строку. Документация `\gset` задаёт строгие правила одной строки результата.
- **\watch interval/count.** Повторяет текущий query buffer. Документация `\watch` описывает interval и count.

### Интерполяция SQL

- **Кавычки при подстановке переменных.** :'имя_переменной'. Форма `:'name'` экранирует значение как SQL literal; для идентификатора используется `:"name"`.
- **Формы :name.** :name. psql поддерживает обычную подстановку, literal/identifier quoting и проверку существования переменной.

### Шаблоны поиска

- **schema.object и regexp элементы.** Точка разделяет шаблон схемы и объекта. Раздел поиска объясняет схему.объект и расширенный pattern matching.
