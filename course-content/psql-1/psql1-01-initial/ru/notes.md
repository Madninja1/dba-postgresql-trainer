# Initial — основы psql

## 1. Тема

`psql` — терминальный клиент PostgreSQL. Он подключается к серверу, передаёт ему SQL-команды и показывает результаты, но при этом имеет собственный язык управления: **метакоманды psql**, начинающиеся с обратной косой черты `\`.

Главное различие первого уровня:

```text
SQL-команда
    ↓
psql передаёт её PostgreSQL server

\метакоманда
    ↓
её обрабатывает сам psql
```

Поэтому `SELECT`, `INSERT`, `CREATE TABLE` — SQL, а `\dt`, `\conninfo`, `\q` — команды клиента. Это разные уровни: сервер PostgreSQL не выполняет `\dt`, а psql не реализует сам логику `SELECT`.

---

# 2. Механизм

## Подключение к PostgreSQL

Общая форма запуска:

```text
psql [параметры...] [имя_бд [имя_пользователя]]
```

Основные параметры подключения:

```text
-d DBNAME    база данных
-h HOST      сервер
-p PORT      порт
-U USER      пользователь PostgreSQL
```

Пример:

```bash
psql -h db.example.org -p 5432 -U app -d appdb
```

Здесь:

```text
-h db.example.org   куда подключаться
-p 5432             к какому порту
-U app              под какой ролью PostgreSQL
-d appdb            к какой базе данных
```

`-d` может принимать не только имя базы, но и строку подключения. Например, psql поддерживает conninfo/URI-форму:

```bash
psql "service=myservice sslmode=require"
psql postgresql://dbmaster:5433/mydb?sslmode=require
```

Не все параметры обязательно указывать. psql использует значения по умолчанию и параметры libpq. Для часто используемых настроек подключения есть переменные окружения:

```text
PGDATABASE   база данных
PGHOST       сервер
PGPORT       порт
PGUSER       пользователь
```

То есть команды

```bash
psql -h localhost -p 5432 -U dba -d postgres
```

и запуск `psql` с заранее заданными `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` решают одну и ту же задачу: сообщают клиенту параметры соединения.

Пароль не относится к этим четырём переменным. Для автоматического получения пароля может использоваться файл `.pgpass`; ключ `-W` принудительно запрашивает пароль, а `-w` запрещает psql запрашивать его интерактивно.

---

## Что происходит после подключения

После успешного подключения psql показывает приглашение, обычно содержащее имя текущей базы:

```text
testdb=>
```

Теперь можно вводить SQL:

```sql
SELECT current_database(), current_user;
```

SQL-команда может занимать несколько строк. **Перевод строки сам по себе обычно не завершает SQL-команду.** psql ждёт завершающую точку с запятой:

```sql
SELECT
    current_database(),
    current_user
;
```

Упрощённая модель:

```text
вводим SQL
   ↓
текст накапливается в psql
   ↓
встречается завершающая ;
   ↓
psql отправляет команду серверу
   ↓
PostgreSQL выполняет её
   ↓
psql отображает результат
```

Это объясняет, почему можно удобно форматировать запрос на нескольких строках.

## Метакоманды psql

Некавыченный ввод, начинающийся с `\`, psql воспринимает как собственную метакоманду.

Примеры:

```text
\conninfo
\dt
\d users
\q
```

Эти команды полезны для навигации по базе, администрирования, просмотра объектов, настройки клиента и написания psql-скриптов.

### Текущее соединение — `\conninfo`

```text
\conninfo
```

Показывает информацию о текущем подключении.

Это первая команда, которую полезно помнить при сомнениях: **куда именно я сейчас подключён?**

---

## Переподключение — `\c` / `\connect`

Внутри уже запущенного psql можно установить новое соединение:

```text
\c mydb
```

или:

```text
\connect mydb
```

Полная позиционная форма позволяет задавать базу, пользователя, host и port:

```text
\c mydb myuser host.example.org 5432
```

Также принимается строка подключения:

```text
\c "host=localhost port=5432 dbname=mydb connect_timeout=10"
```

Не путайте:

```text
-d mydb     выбрать базу при запуске psql
\c mydb     сменить подключение уже внутри psql
```

## Базовая навигация по объектам

Для ежедневной работы достаточно выучить несколько команд:

```text
\l     базы данных
\dn    схемы
\du    роли
\dt    таблицы
```

`` в этих командах нет: буквы имеют конкретный смысл. Например, `t` в `\dt` означает tables.

### Список баз — `\l` / `\list`

```text
\l
```

или:

```text
\list
```

Показывает базы данных сервера, в том числе их владельцев, кодировки и права доступа. Вариант `\l+` добавляет дополнительную информацию.

### Таблицы — `\dt`

```text
\dt
```

Показывает видимые таблицы.

### Схемы — `\dn`

```text
\dn
```

Показывает схемы.

### Роли — `\du`

```text
\du
```

Показывает роли базы данных. В PostgreSQL понятия пользователей и групп объединены в роли, поэтому `\du` фактически работает со списком ролей.

Запоминать удобно так:

```text
\l     list databases
\dn    namespaces (schemas)
\du    users/roles
\dt    tables
```

---

## Описание объекта — `\d`

`\d` — одна из самых полезных групп команд psql.

Например:

```text
\d users
```

Для таблицы команда показывает не просто имена столбцов. В описании могут присутствовать:

- столбцы и их типы;
- `NOT NULL`;
- значения по умолчанию;
- связанные индексы;
- ограничения;
- правила;
- триггеры.

Вариант с `+` даёт больше информации:

```text
\d+ users
```

`+` у многих `\d*`-команд означает **расширенный вывод**, но конкретный набор дополнительных полей зависит от типа объекта.

Если написать `\d` без шаблона, psql выводит список видимых отношений нескольких типов, а не описание одной конкретной таблицы.

## Встроенная справка

У psql есть две разные справочные системы.

### Справка самого psql — `\?`

```text
\?
```

Показывает справку по psql. Команда принимает тему:

```text
\? commands
\? options
\? variables
```

Если тему не указать, по умолчанию используется `commands`.

Те же категории доступны при запуске программы:

```bash
psql --help=commands
psql --help=options
psql --help=variables
```

Основные допустимые темы:

```text
commands
options
variables
```

`indexes` отдельной темой `--help` не является.

### Справка по SQL — `\h` / `\help`

```text
\h SELECT
\h CREATE TABLE
```

Эта команда показывает синтаксис SQL-команды PostgreSQL.

Разница:

```text
\?       как пользоваться psql
\h       как записывается SQL-команда
```

## Выполнение команды через `-c`

Одну команду можно передать прямо из shell:

```bash
psql -d appdb -c 'SELECT now();'
```

`-c` / `--command`:

- передаёт psql команду для выполнения;
- может использоваться несколько раз;
- может комбинироваться с `-f`;
- после обработки всех `-c`/`-f` psql завершается.

Аргумент одного `-c` должен быть либо строкой, полностью интерпретируемой сервером, либо **одной** backslash-метакомандой. Поэтому нельзя рассчитывать, что один `-c` свободно смешает SQL и метакоманды psql.

Допустимо:

```bash
psql -c '\x' -c 'SELECT * FROM users;'
```

Здесь используются два отдельных `-c`.

Важная деталь: строка SQL, переданная одним `-c`, отправляется серверу как **один запрос**. Транзакционные последствия этого подробно рассматриваются на Strong-уровне.

---

## Выполнение файла через `-f`

```bash
psql -d appdb -f script.sql
```

`-f` / `--file` читает команды из файла вместо стандартного ввода.

Его можно:

```text
повторять
комбинировать с -c
```

Например:

```bash
psql -f prepare.sql -c 'SELECT now();' -f finish.sql
```

Команды обрабатываются в указанном порядке.

`-f script.sql` похож на:

```bash
psql < script.sql
```

но это **не полные эквиваленты во всех деталях**. Например, при `-f` psql может указывать номера строк в сообщениях об ошибках.

Внутри интерактивного psql похожую задачу решает:

```text
\i script.sql
```

Подробности `\i` и работы со скриптами будут в Middle.

---

## Выход из psql

```text
\q
```

или:

```text
\quit
```

завершает psql.

Не путайте с:

```text
\r    очистить текущий query buffer
\p    показать query buffer
\g    выполнить query buffer
```

Эти команды работают с запросом и рассматриваются на следующем уровне.

# 3. Важные детали

## Параметры запуска и метакоманды — не одно и то же

Одна и та же задача иногда имеет форму для shell и форму для уже работающего psql:

```text
при запуске       внутри psql
--------------------------------
-d mydb           \c mydb
--help=commands   \? commands
-l                \l
-x                \x
```

Контекст определяет синтаксис: `-d` обрабатывается при запуске программы, а `\c` — внутри psql.

---

## `\d` — это не SQL

Команда:

```text
\d users
```

не отправляется серверу как текст `\d users`. psql сам реализует метакоманду и при необходимости обращается к системным каталогам PostgreSQL.

На продвинутом уровне можно включить `ECHO_HIDDEN` и увидеть SQL, который psql генерирует для таких команд.

---

## Не путайте базу, пользователя, host и port

```text
-d   database
-h   host
-p   port
-U   user
```

Удобная мнемоника:

```text
psql -h КУДА -p КАКОЙ_ПОРТ -U КТО -d КАКАЯ_БАЗА
```

# Что запомнить

Главная модель:

```text
psql
 ├─ подключается к PostgreSQL
 ├─ отправляет SQL серверу
 ├─ показывает результат
 └─ сам обрабатывает \метакоманды
```

Подключение:

```text
-d DBNAME
-h HOST
-p PORT
-U USER
```

Эквивалентные переменные среды:

```text
PGDATABASE
PGHOST
PGPORT
PGUSER
```

Навигация:

```text
\conninfo   текущее соединение
\c          переподключиться
\l          базы данных
\dn         схемы
\du         роли
\dt         таблицы
\d object   описание объекта
\q          выход
```

Справка:

```text
\?              справка psql
\? commands     метакоманды
\? options      параметры запуска
\? variables    переменные psql
\h SELECT       справка SQL
```

Запуск без интерактивного ввода:

```text
-c command      выполнить команду
-f file.sql     выполнить файл
```

И два правила, которые нельзя путать:

```text
перевод строки       ≠ конец SQL-команды
завершающая ;        → обычно отправляет SQL серверу

SQL                  → выполняет PostgreSQL
\метакоманда         → обрабатывает psql
```
