# Роли, права и безопасность

## 1. Тема

Тема посвящена системным каталогам PostgreSQL и связям между ними: где сервер хранит метаданные объектов и какие поля позволяют восстановить структуру и состояние базы.

```text

        ↓
понимание механизма
        ↓

        ↓

```

## 2. Механизм

Эта тема связывает каталоги ролей, членства, прав по умолчанию, RLS и security labels.

### pg_authid и pg_roles

`pg_authid` хранит роли и является shared catalog. Он содержит чувствительное поле пароля, поэтому прямой доступ ограничен.

Для обычного просмотра предназначено представление `pg_roles`, где пароль скрыт.

Важные флаги `pg_authid`:

- `rolsuper` — суперпользователь;
- `rolinherit` — наследование прав членства;
- `rolcreaterole`;
- `rolcreatedb`;
- `rolcanlogin` — роль может подключаться;
- `rolreplication`;
- `rolbypassrls`.

### pg_auth_members

Описывает членство ролей:

- `roleid` — роль, в которую включают;
- `member` — включаемая роль;
- `grantor` — кто выдал членство;
- `admin_option` — member может выдавать это членство другим;
- `inherit_option` — наследовать привилегии;
- `set_option` — разрешён `SET ROLE`.

### pg_db_role_setting

Хранит значения runtime-параметров по умолчанию для комбинаций роль/база данных — то, что задаётся командами вроде `ALTER ROLE ... SET` и `ALTER DATABASE ... SET`.

### pg_default_acl

Описывает **права по умолчанию для будущих объектов**, а не ретроактивное изменение ACL уже существующих объектов.

Ключевые поля:

- `defaclrole` — роль;
- `defaclnamespace` — схема или 0 для глобальной записи;
- `defaclobjtype` — тип объектов;
- `defaclacl` — ACL.

### pg_init_privs

Хранит начальные привилегии объектов, чтобы PostgreSQL мог различать исходные и изменённые права. `privtype = 'e'` означает права, установленные в процессе `CREATE EXTENSION`.

### pg_parameter_acl

Shared catalog для параметров конфигурации, на которые были назначены нестандартные права:

- `parname` — имя GUC;
- `paracl` — ACL.

Он не содержит вообще все параметры — только те, где есть соответствующие ACL.

### pg_policy и RLS

`pg_policy` хранит политики Row Level Security.

`polcmd`:

```text
r  SELECT
a  INSERT
w  UPDATE
d  DELETE
*  ALL
```

Наличие записи в `pg_policy` само по себе недостаточно: на таблице должен быть включён RLS (`pg_class.relrowsecurity`).

### Security labels

- `pg_seclabel` — метки безопасности объектов текущей базы;
- `pg_shseclabel` — метки shared-объектов кластера.

`pg_seclabel` хранит объект, провайдера и текст метки.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 53.8. pg_authid

- **Назначение каталога ролей.** pg_authid хранит роли. Понятия пользователей и групп в PostgreSQL реализованы через роли.
- **Ограничение доступа и представление pg_roles.** pg_authid содержит поле пароля. pg_authid содержит парольные данные, поэтому для общего использования документация указывает представление pg_roles, где пароль очищен.
- **Столбец rolcanlogin.** rolcanlogin=true означает, что роль может использоваться как начальный идентификатор авторизации сеанса.

### 53.9. pg_auth_members

- **roleid, member, admin_option, inherit_option, set_option.** roleid указывает роль, включающую другую. pg_auth_members описывает членство между ролями и связанные опции admin/inherit/set.

### 53.16. pg_db_role_setting

- **Назначение каталога; setdatabase, setrole, setconfig.** Для значений runtime-параметров по умолчанию для комбинаций ролей и баз. pg_db_role_setting хранит значения конфигурационных переменных по умолчанию для различных комбинаций роли и базы данных.

### 53.17. pg_default_acl

- **Назначение и область действия default ACL.** Он хранит начальные права, назначаемые вновь создаваемым объектам. pg_default_acl влияет на права при создании объектов. Изменение default ACL не переписывает уже существующие ACL.

### 53.28. pg_init_privs

- **Столбец privtype.** Начальные права были назначены в процессе CREATE EXTENSION. В pg_init_privs `i` означает права от initdb, а `e` — права, записанные при CREATE EXTENSION.

### 53.36. pg_parameter_acl

- **Назначение; parname; paracl; shared catalog.** Каталог содержит параметры конфигурации, для которых назначены нестандартные права. pg_parameter_acl содержит только параметры, для которых были назначены права одной или нескольким ролям; параметры со стандартными правами отсутствуют.

### 53.38. pg_policy

- **Назначение каталога RLS.** pg_policy хранит политики защиты строк для таблиц.
- **Столбец polcmd.** `r` — SELECT. polcmd кодирует команду, к которой применяется RLS policy: r/a/w/d/*.
- **Примечание о pg_class.relrowsecurity.** У таблицы должно быть включено pg_class.relrowsecurity. Документация отмечает, что политики из pg_policy применяются только когда у таблицы установлено свойство pg_class.relrowsecurity.

### 53.50. pg_shseclabel

- **Назначение shared security labels.** pg_seclabel хранит метки безопасности объектов базы данных. pg_seclabel относится к объектам конкретной базы, а pg_shseclabel — к глобальным объектам и является shared catalog.

### 53.46. pg_seclabel

- **Назначение; provider; label.** Метки безопасности объектов базы данных вместе с provider и label. pg_seclabel хранит security labels объектов базы; provider указывает поставщика метки, label — саму метку.
