# Ядро каталогов: отношения, столбцы, типы и базы

## 1. Тема

Тема посвящена системным каталогам PostgreSQL и связям между ними: где сервер хранит метаданные объектов и какие поля позволяют восстановить структуру и состояние базы.

## 2. Механизм

Системные каталоги PostgreSQL — обычные таблицы с метаданными и служебными сведениями. Большинство каталогов принадлежат конкретной базе, но некоторые разделяются всем кластером.

### pg_class

`pg_class` описывает отношения: таблицы, индексы, последовательности, представления, materialized views и другие объекты.

Ключевые поля:

- `relname` — имя;
- `relnamespace` — схема (`pg_namespace`);
- `relowner` — владелец;
- `relkind` — тип отношения;
- `reltuples` — **оценка** числа актуальных строк, а не точный `count(*)`.

Частые `relkind`:

```text
r  ordinary table
i  index
S  sequence
v  view
m  materialized view
p  partitioned table
f  foreign table
```

### pg_attribute и pg_attrdef

`pg_attribute` содержит строку для каждого столбца каждого отношения.

Полезные поля:

- `attrelid` — отношение;
- `attname` — имя столбца;
- `atttypid` — тип (`pg_type`);
- `attnum` — номер столбца;
- `attnotnull` — `NOT NULL`;
- `atthasdef` — есть default/generated expression;
- `attisdropped` — столбец логически удалён.

Обычные столбцы имеют `attnum` от 1, системные обычно используют отрицательные номера.

Само выражение `DEFAULT` хранится в `pg_attrdef.adbin`; для получения SQL-текста применяют `pg_get_expr(adbin, adrelid)`.

### pg_namespace

Каталог пространств имён, на которых основаны SQL-схемы:

- `nspname` — имя;
- `nspowner` — владелец;
- `nspacl` — ACL.

### pg_type

Содержит типы данных. В `typtype` встречаются, например:

```text
b  base type
c  composite
d  domain
e  enum
p  pseudo-type
r  range
m  multirange
```

### pg_database

Каталог баз данных кластера и один из shared catalogs.

- `datname` — имя;
- `datallowconn` — разрешены ли подключения;
- `datconnlimit = -1` — ограничения числа подключений нет.

### pg_sequence

Хранит параметры последовательностей: старт, шаг, минимум, максимум, cache и cycle. Сама последовательность как отношение также имеет запись в `pg_class`.

### pg_enum

- `enumtypid` — enum-тип;
- `enumlabel` — текстовая метка;
- `enumsortorder` — порядок значения.

### pg_collation

Описывает правила сортировки.

- `collname` — имя;
- `collprovider` — провайдер (`c` libc, `i` ICU и др.);
- `collencoding = -1` — применимо к любой кодировке;
- `collversion` — версия collation от провайдера.

### pg_tablespace

Каталог табличных пространств. Он разделяется всеми базами кластера.

#### Практический запрос

```sql
SELECT n.nspname, c.relname, c.relkind, c.reltuples
FROM pg_class AS c
JOIN pg_namespace AS n ON n.oid = c.relnamespace
WHERE n.nspname NOT LIKE 'pg_%';
```

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 53.1. Обзор

- **Обзор системных каталогов и рекомендация не изменять их вручную.** Обычные таблицы, в которых PostgreSQL хранит метаданные и служебные сведения. Глава 53 описывает системные каталоги как обычные таблицы PostgreSQL. При этом вручную модифицировать их обычно не следует: для этого предусмотрены SQL-команды.
- **Обзор: локальные для базы и разделяемые каталоги.** Большинство каталогов копируются из базы-шаблона и принадлежат конкретной базе. Большинство каталогов относятся к конкретной базе, но часть каталогов разделяется всем кластером; pg_database — один из таких каталогов.

### 53.11. pg_class

- **Назначение каталога; relkind.** pg_class содержит строки для отношений разных видов: таблиц, индексов, последовательностей, представлений, materialized views, TOAST-таблиц и других объектов.
- **Столбец relkind.** `r` — обычная таблица. relkind кодирует вид отношения. В материале перечислены r, i, S, t, v, m, c, f, p и I; `x` как внешний сервер там не используется.
- **Столбец reltuples.** Примерную оценку числа актуальных строк, используемую планировщиком. reltuples — приблизительная оценка количества актуальных строк. Она обновляется VACUUM, ANALYZE и некоторыми DDL-командами; -1 означает неизвестное количество.

### 53.7. pg_attribute

- **Назначение; attname; attnum; attisdropped.** Для каждого столбца каждого отношения есть строка в pg_attribute. pg_attribute описывает атрибуты/столбцы. Удалённые столбцы могут сохраняться как записи с attisdropped=true.

### 53.6. pg_attrdef

- **Назначение pg_attrdef; adbin.** pg_attribute.atthasdef лишь указывает на наличие default/generated expression; само выражение для столбца хранится в pg_attrdef.

### 53.32. pg_namespace

- **Назначение; nspname; nspowner; nspacl.** Каталог хранит пространства имён, на которых основаны SQL-схемы. pg_namespace описывает пространства имён/схемы: имя, владельца и ACL.

### 53.64. pg_type

- **Столбец typtype.** В pg_type.typtype: b — base, c — composite, d — domain, e — enum, p — pseudo-type, r — range, m — multirange.

### 53.15. pg_database

- **Назначение; datname; datallowconn; datconnlimit.** datname хранит имя базы. pg_database — разделяемый каталог уровня кластера. Он содержит имя базы, возможность подключения и лимит соединений среди прочих свойств.

### 53.47. pg_sequence

- **Назначение и параметры последовательности.** pg_sequence хранит seqstart, seqincrement, seqmax, seqmin, seqcache и seqcycle; имя и схема последовательности при этом находятся в pg_class.

### 53.20. pg_enum

- **enumlabel и enumsortorder.** pg_enum.enumlabel хранит текстовую метку значения enum. pg_enum описывает значения перечислений и их порядок, а pg_collation — доступные правила сортировки и их провайдер/кодировку.

### 53.56. pg_tablespace

- **Назначение pg_tablespace; shared catalog.** pg_tablespace хранит доступные tablespaces; каталог является общим для всего кластера.

### 53.12. pg_collation

- **collname, collprovider, collencoding, collversion.** collname — имя правила сортировки. pg_collation описывает правила сортировки, их provider, encoding и версию.
