## 2. Механизм

Этот уровень — база SQL в PostgreSQL: как устроены таблицы, как читать и изменять данные, как соединять таблицы и как работают простейшие транзакции.

### Таблица и отношение

В реляционной модели таблица — это **отношение**. Таблица состоит из строк и именованных столбцов, каждому столбцу назначен тип данных. Порядок строк сам по себе не гарантируется: если нужен стабильный порядок, используйте `ORDER BY`.

```sql
CREATE TABLE users (
    id integer,
    name text,
    created_at timestamp
);
```

### INSERT, SELECT, UPDATE, DELETE

Добавление строк:

```sql
INSERT INTO users (id, name)
VALUES (1, 'Alice');
```

Явное перечисление столбцов обычно безопаснее, чем зависимость от их физического порядка.

Чтение данных:

```sql
SELECT id, name
FROM users
WHERE id > 0
ORDER BY name;
```

`SELECT *` означает «все столбцы». В учебных и диагностических запросах это удобно, но в прикладном коде лучше перечислять нужные столбцы явно.

Изменение и удаление:

```sql
UPDATE users
SET name = 'Bob'
WHERE id = 1;

DELETE FROM users
WHERE id = 1;
```

`DELETE` без `WHERE` удаляет **все строки** таблицы.

### WHERE, ORDER BY и DISTINCT

- `WHERE` фильтрует отдельные строки.
- `ORDER BY` задаёт порядок результата.
- `DISTINCT` удаляет дубликаты из результата.

```sql
SELECT DISTINCT city
FROM weather
ORDER BY city;
```

### JOIN

`JOIN` объединяет строки разных таблиц по условию.

```sql
SELECT w.city, c.location
FROM weather AS w
JOIN cities AS c ON c.name = w.city;
```

Обычный `JOIN` — внутренний: строки без соответствия отбрасываются.

`LEFT JOIN` сохраняет все строки левой таблицы. Если справа соответствия нет, столбцы правой таблицы получают `NULL`.

```sql
SELECT *
FROM weather AS w
LEFT JOIN cities AS c ON c.name = w.city;
```

### Агрегаты, GROUP BY и HAVING

Базовые агрегаты:

- `count` — количество;
- `sum` — сумма;
- `avg` — среднее;
- `min` — минимум;
- `max` — максимум.

```sql
SELECT city, count(*), max(temp_hi)
FROM weather
GROUP BY city;
```

`WHERE` фильтрует строки **до** группировки, `HAVING` — уже полученные группы.

```sql
SELECT city, count(*)
FROM weather
WHERE temp_hi > 0
GROUP BY city
HAVING count(*) > 1;
```

Для отдельного агрегата можно использовать `FILTER`:

```sql
SELECT
    count(*) FILTER (WHERE temp_hi > 20),
    count(*)
FROM weather;
```

### COPY

`COPY` предназначен для массовой загрузки/выгрузки данных. Серверный `COPY ... FROM 'file'` читает файл на стороне сервера PostgreSQL, а не на машине клиента.

### Транзакции

Транзакция объединяет несколько действий в операцию «всё или ничего».

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;
```

Для отмены используется `ROLLBACK`.

`SAVEPOINT` позволяет откатить только часть транзакции:

```sql
SAVEPOINT s1;
-- изменения
ROLLBACK TO s1;
```

### Идентификаторы

Ключевые слова SQL и обычные незаключённые в кавычки идентификаторы нечувствительны к регистру и приводятся PostgreSQL к нижнему регистру. Двойные кавычки сохраняют регистр идентификатора.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 2.2. Основные понятия

- **Отношение и таблица.** Таблицу. В учебном введении отношение используется как математически точное обозначение таблицы.

### 2.3. Создание таблицы

- **CREATE TABLE.** Таблица создаётся командой CREATE TABLE с именами столбцов и их типами.

### 2.4. Добавление строк в таблицу

- **INSERT INTO.** Для добавления строк используется INSERT; список столбцов можно указать явно.
- **Явный список столбцов.** Можно явно перечислить столбцы. Явный список столбцов делает INSERT менее зависимым от порядка столбцов таблицы.
- **COPY FROM файла.** COPY подходит для загрузки большого объёма данных. В примере COPY читает серверный файл и описывается как оптимизированный способ массовой загрузки.

### 2.5. Выполнение запроса

- **SELECT *.** Все столбцы. `*` является краткой записью выбора всех столбцов.
- **WHERE.** WHERE проверяет логическое условие для строк и оставляет строки, для которых условие истинно.
- **ORDER BY.** ORDER BY используется для явного задания порядка результата.
- **DISTINCT.** Использовать DISTINCT. DISTINCT удаляет дубликаты из результата; порядок при этом сам по себе не гарантируется.

### 2.6. Соединения таблиц

- **LEFT OUTER JOIN.** Они остаются в результате, а столбцы правой стороны заполняются NULL. Левое внешнее соединение сохраняет все строки левой стороны.
- **JOIN и self join.** JOIN может обращаться к нескольким таблицам. Материал показывает обычные JOIN, внешнее соединение и self join с псевдонимами.

### 2.7. Агрегатные функции

- **count.** Введение перечисляет count, sum, avg, max и min как агрегатные функции.
- **Список агрегатных функций.** count. Эти пять агрегатных функций приведены как базовые примеры.
- **WHERE и HAVING.** WHERE фильтрует строки до группировки. Материал отдельно объясняет порядок и назначение WHERE и HAVING.

### 2.4, 2.8, 2.9

- **INSERT / UPDATE / DELETE.** INSERT. Главы 2.4, 2.8 и 2.9 показывают добавление, изменение и удаление строк.

### 3.4. Транзакции

- **BEGIN, COMMIT, ROLLBACK, SAVEPOINT.** BEGIN начинает явный блок транзакции. Материал описывает принцип «всё или ничего», BEGIN/COMMIT/ROLLBACK и точки сохранения.

### 4.1.1. Идентификаторы и ключевые слова

- **Регистр и двойные кавычки.** Идентификаторы без кавычек приводятся к нижнему регистру. Глава синтаксиса различает некавыченные и двойным образом кавыченные идентификаторы.

### 2.9. Удаление данных

- **DELETE без WHERE.** Он удаляет все строки таблицы. Материал прямо предупреждает, что DELETE FROM table без условия полностью очищает строки таблицы.
