# Initial — основы SQL

## 1. Тема

SQL — язык работы с реляционными данными. На первом уровне важно не запоминать команды по отдельности, а понимать общий цикл:

```text
описать структуру таблицы
        ↓
добавить данные
        ↓
выбрать нужные строки и столбцы
        ↓
соединить данные из нескольких таблиц
        ↓
сгруппировать и посчитать
        ↓
изменить или удалить данные
```

PostgreSQL — реляционная СУБД. В базовом объяснении **relation** соответствует таблице: у неё есть именованные столбцы с типами и строки с данными.

Важно: SQL не гарантирует порядок строк сам по себе. Если порядок результата имеет значение, его нужно задавать через `ORDER BY`.

---

## 2. Таблицы и типы данных

Таблица создаётся командой `CREATE TABLE`:

```sql
CREATE TABLE users (
    id integer,
    name text,
    created_at timestamp
);
```

Здесь:

```text
users       имя таблицы
id          столбец integer
name        столбец text
created_at  столбец timestamp
```

Тип определяет, какие значения может хранить столбец и какие операции с ними допустимы.

Для удаления таблицы используется:

```sql
DROP TABLE users;
```

`DROP TABLE` удаляет сам объект таблицы вместе с её данными. Это не то же самое, что `DELETE`, который удаляет строки, оставляя таблицу существовать.

---

## 3. INSERT — добавление строк

Строки добавляются через `INSERT`:

```sql
INSERT INTO users (id, name, created_at)
VALUES (1, 'Alice', '2026-01-10 12:00:00');
```

Лучше явно перечислять столбцы:

```sql
INSERT INTO users (name, id)
VALUES ('Bob', 2);
```

Так запрос не зависит от физического порядка столбцов в таблице и сразу показывает, куда попадает каждое значение.

Можно встретить сокращённую запись:

```sql
INSERT INTO users
VALUES (3, 'Carol', '2026-01-11 09:30:00');
```

Она требует точного знания порядка столбцов и поэтому хуже переносит изменение структуры таблицы.

Для массовой загрузки данных PostgreSQL поддерживает `COPY`. В серверной форме:

```sql
COPY users FROM '/path/users.txt';
```

указанный файл читает **сервер PostgreSQL**, а не клиент, из которого была отправлена команда. `COPY` оптимизирован для массовой загрузки и обычно подходит для неё лучше серии одиночных `INSERT`.

---

## 4. SELECT — чтение данных

Базовая форма:

```sql
SELECT id, name
FROM users;
```

`SELECT` формирует результат запроса, `FROM` указывает источник данных.

```sql
SELECT *
FROM users;
```

`*` означает «все столбцы».

Для разового просмотра это удобно. В прикладном коде полезнее перечислять нужные столбцы явно: результат не изменится неожиданно после добавления нового столбца в таблицу.

В списке `SELECT` могут быть выражения:

```sql
SELECT
    city,
    (temp_hi + temp_lo) / 2 AS temp_avg
FROM weather;
```

`AS` задаёт имя результирующему столбцу.

---

## 5. WHERE — фильтрация строк

`WHERE` оставляет только строки, для которых условие истинно:

```sql
SELECT city, temp_hi
FROM weather
WHERE temp_hi > 25;
```

Условия можно объединять:

```sql
SELECT city, temp_hi
FROM weather
WHERE city = 'San Francisco'
  AND temp_hi > 20;
```

Основные логические операторы:

```text
AND  оба условия должны быть истинны
OR   достаточно одного истинного условия
NOT  логическое отрицание
```

`WHERE` работает со строками **до** группировки и вычисления агрегатов. Это станет особенно важно при `GROUP BY`.

---

## 6. ORDER BY и DISTINCT

Без `ORDER BY` порядок строк результата не определён.

```sql
SELECT city, temp_lo
FROM weather
ORDER BY city, temp_lo;
```

Сортировка выполняется сначала по `city`, затем внутри одинаковых городов по `temp_lo`.

Чтобы убрать повторяющиеся строки результата, используется `DISTINCT`:

```sql
SELECT DISTINCT city
FROM weather
ORDER BY city;
```

`DISTINCT` отвечает за уникальность результата, но сам по себе не обязан его сортировать. Если нужен стабильный порядок, всё равно используйте `ORDER BY`.

## 7. JOIN — соединение таблиц

Реляционные данные обычно разделены между несколькими таблицами. `JOIN` позволяет собрать связанные строки в одном результате.

```sql
SELECT
    w.city,
    w.temp_hi,
    c.location
FROM weather AS w
JOIN cities AS c
    ON c.name = w.city;
```

`AS w` и `AS c` — псевдонимы таблиц. Они сокращают запись и помогают однозначно указывать столбцы:

```text
w.city      city из weather
c.location  location из cities
```

Обычный `JOIN` — это внутреннее соединение (`INNER JOIN`): в результат попадают только строки, для которых найдено соответствие по условию `ON`.

### LEFT JOIN

```sql
SELECT
    w.city,
    c.location
FROM weather AS w
LEFT JOIN cities AS c
    ON c.name = w.city;
```

`LEFT JOIN` сохраняет **все строки левой таблицы**. Если соответствующей строки справа нет, столбцы правой таблицы получают `NULL`.

Упрощённая модель:

```text
INNER JOIN  → только совпавшие пары
LEFT JOIN   → все слева + совпадения справа
```

### Self join

Таблицу можно соединить с самой собой. Тогда псевдонимы обязательны практически по смыслу, потому что нужно различать две роли одной таблицы:

```sql
SELECT w1.city, w2.city
FROM weather AS w1
JOIN weather AS w2
    ON w1.temp_lo < w2.temp_lo;
```

## 8. Агрегаты и GROUP BY

Агрегатная функция получает набор строк и вычисляет одно значение.

Базовые агрегаты:

```text
count  количество
sum    сумма
avg    среднее
min    минимум
max    максимум
```

Например:

```sql
SELECT count(*)
FROM weather;
```

Чтобы вычислять агрегаты отдельно для разных групп, используется `GROUP BY`:

```sql
SELECT
    city,
    count(*) AS measurements,
    max(temp_hi) AS max_temp
FROM weather
GROUP BY city;
```

После `GROUP BY city` каждая группа состоит из строк одного города, и агрегаты считаются отдельно для каждой группы.

### WHERE и HAVING

Это принципиально разные фильтры:

```text
WHERE   фильтрует исходные строки
GROUP BY формирует группы
HAVING  фильтрует уже сформированные группы
```

```sql
SELECT city, count(*)
FROM weather
WHERE temp_hi > 0
GROUP BY city
HAVING count(*) > 1;
```

Здесь сначала отбрасываются строки с `temp_hi <= 0`, затем оставшиеся строки группируются, после чего `HAVING` оставляет только группы с более чем одной строкой.

Для фильтрации входа только одного агрегата PostgreSQL поддерживает `FILTER`:

```sql
SELECT
    count(*) AS all_rows,
    count(*) FILTER (WHERE temp_hi > 20) AS warm_rows
FROM weather;
```

Оба агрегата видят один запрос, но второй считает только строки, прошедшие его собственный фильтр.

## 9. UPDATE и DELETE

Изменение существующих строк:

```sql
UPDATE users
SET name = 'Robert'
WHERE id = 2;
```

Удаление строк:

```sql
DELETE FROM users
WHERE id = 2;
```

Главное правило безопасности:

```sql
DELETE FROM users;
```

без `WHERE` удаляет **все строки таблицы**.

То же мышление нужно применять к `UPDATE`: если забыть `WHERE`, изменение затронет все строки.

---

## 10. Транзакции

Транзакция объединяет несколько SQL-команд в одну логическую операцию.

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE name = 'Alice';

UPDATE accounts
SET balance = balance + 100
WHERE name = 'Bob';

COMMIT;
```

Идея:

```text
BEGIN
  ↓
несколько связанных изменений
  ↓
COMMIT   сохранить всё
или
ROLLBACK отменить всё
```

Если операция не должна быть зафиксирована:

```sql
ROLLBACK;
```

PostgreSQL также поддерживает точки сохранения:

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE name = 'Alice';

SAVEPOINT before_receiver;

UPDATE accounts
SET balance = balance + 100
WHERE name = 'Bob';

ROLLBACK TO before_receiver;

UPDATE accounts
SET balance = balance + 100
WHERE name = 'Wally';

COMMIT;
```

`ROLLBACK TO` отменяет изменения после точки сохранения, но не отменяет всю транзакцию.

## 11. Идентификаторы и регистр

Ключевые слова обычно пишут верхним регистром только для читаемости:

```sql
SELECT name FROM users;
```

PostgreSQL приводит **незаключённые в кавычки идентификаторы** к нижнему регистру.

```sql
CREATE TABLE Users (...);
```

для PostgreSQL фактически создаёт имя `users`.

Двойные кавычки делают идентификатор чувствительным к регистру:

```sql
CREATE TABLE "Users" (...);
```

Теперь `"Users"` и `users` — разные имена. Поэтому без необходимости смешанный регистр и кавычки в именах объектов обычно только усложняют работу.

Строковые значения, напротив, записываются в **одинарных** кавычках:

```sql
SELECT 'Alice';
```

# Что запомнить

Главная последовательность первого уровня:

```text
CREATE TABLE  создать структуру
INSERT        добавить строки
SELECT        получить данные
WHERE         отфильтровать строки
ORDER BY      задать порядок
DISTINCT      убрать дубликаты результата
JOIN          связать таблицы
GROUP BY      сформировать группы
HAVING        отфильтровать группы
UPDATE        изменить строки
DELETE        удалить строки
```

Ключевые различия:

```text
INNER JOIN  → только совпавшие строки
LEFT JOIN   → все строки слева, отсутствие справа = NULL

WHERE       → до группировки
HAVING      → после группировки

DELETE ... WHERE ... → выбранные строки
DELETE без WHERE      → все строки

COMMIT      → зафиксировать транзакцию
ROLLBACK    → отменить транзакцию
ROLLBACK TO → откатиться к SAVEPOINT
```

И ещё три правила:

1. Нужен гарантированный порядок — пишите `ORDER BY`.
2. В `INSERT` и прикладном `SELECT` лучше явно перечислять столбцы.
3. Перед `UPDATE` или `DELETE` всегда проверяйте условие `WHERE`.
