## 2. Механизм

Здесь важны прикладные конструкции PostgreSQL: ограничения целостности, схемы, подзапросы, операции над наборами, оконные функции, массивы/JSON и `RETURNING`.

### Ограничения и внешние ключи

Ограничения защищают данные на уровне базы. К основным относятся `CHECK`, `NOT NULL`, `UNIQUE`, `PRIMARY KEY` и `FOREIGN KEY`.

```sql
CREATE TABLE orders (
    id bigint PRIMARY KEY,
    customer_id bigint REFERENCES customers(id),
    amount numeric CHECK (amount >= 0)
);
```

Внешний ключ требует, чтобы ссылающееся значение соответствовало строке целевой таблицы, если правила ограничения не допускают иное.

### Представления

Представление присваивает имя запросу и позволяет обращаться к нему подобно таблице:

```sql
CREATE VIEW active_users AS
SELECT id, name
FROM users
WHERE active;
```

### RETURNING

`RETURNING` возвращает строки, затронутые `INSERT`, `UPDATE` или `DELETE`.

```sql
INSERT INTO users(name)
VALUES ('Alice')
RETURNING id, name;
```

Это удобно, когда после изменения данных сразу нужен созданный идентификатор или новое состояние строки.

### Подзапросы и EXISTS

`EXISTS` проверяет, вернул ли подзапрос хотя бы одну строку:

```sql
SELECT c.id
FROM customers AS c
WHERE EXISTS (
    SELECT 1 FROM orders AS o WHERE o.customer_id = c.id
);
```

Подзапрос может находиться и в `FROM`; тогда он выступает как табличное выражение и должен иметь псевдоним.

### UNION, INTERSECT, EXCEPT

Операции над совместимыми результатами:

- `UNION` — объединение, дубликаты удаляются;
- `UNION ALL` — объединение с сохранением дубликатов;
- `INTERSECT` — пересечение;
- `EXCEPT` — строки первого результата, которых нет во втором.

### Оконные функции

Оконные функции вычисляют значение по связанным строкам, но **не сворачивают** их в одну строку, как обычная агрегация.

```sql
SELECT
    department,
    salary,
    avg(salary) OVER (PARTITION BY department) AS dept_avg
FROM employees;
```

`PARTITION BY` делит строки окна на группы. `ORDER BY` внутри `OVER` задаёт порядок обработки внутри окна.

Оконные функции непосредственно разрешены в списке `SELECT` и в `ORDER BY`.

### Массивы

PostgreSQL поддерживает массивы как тип данных:

```sql
CREATE TABLE t (tags text[]);
SELECT ARRAY['sql', 'postgres'];
```

Элементы и срезы можно получать индексированием. Важно отличать массив SQL от JSON-массива: это разные типы и наборы операторов.

### JSON и JSONB

`jsonb` хранит JSON в разобранном двоичном представлении и хорошо подходит для поиска и индексирования.

```sql
SELECT payload->>'name'
FROM events;
```

JSON/JSONB позволяют хранить объекты и массивы, извлекать поля и использовать SQL/JSON функции и пути.

### Условные выражения

Часто используются:

- `CASE`;
- `COALESCE` — первое не-`NULL` значение;
- `NULLIF`;
- `GREATEST` и `LEAST`.

```sql
SELECT COALESCE(display_name, login, 'unknown');
```

### Схемы и search_path

Схема — пространство имён для объектов базы. Один и тот же объект можно адресовать полным именем `schema.object`.

`search_path` определяет, в каких схемах PostgreSQL ищет объект без явно указанной схемы. Порядок схем важен и влияет на разрешение имён.

### SAVEPOINT

Точка сохранения позволяет отменить часть транзакции, не отменяя её целиком:

```sql
SAVEPOINT before_step;
-- ...
ROLLBACK TO before_step;
```
