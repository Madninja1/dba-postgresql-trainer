# Strong — продвинутый SQL

## 2. Механизм

Уровень Strong — это составные запросы, продвинутые окна, CTE, индексы, планы выполнения и конкурентный доступ.

### LATERAL

`LATERAL` позволяет подзапросу в `FROM` ссылаться на столбцы элементов `FROM`, расположенных левее него.

```sql
SELECT u.id, x.last_order
FROM users AS u
LEFT JOIN LATERAL (
    SELECT max(created_at) AS last_order
    FROM orders AS o
    WHERE o.user_id = u.id
) AS x ON true;
```

Без `LATERAL` такой подзапрос не может зависеть от текущей строки `u`.

### Табличные функции и WITH ORDINALITY

`WITH ORDINALITY` добавляет к строкам результата табличной функции дополнительный столбец с последовательным номером строки, начиная с 1.

```sql
SELECT *
FROM unnest(ARRAY['a','b']) WITH ORDINALITY AS t(value, n);
```

### GROUPING SETS, ROLLUP, CUBE

Эти конструкции позволяют получить несколько вариантов группировки одним запросом.

```sql
SELECT region, product, sum(amount)
FROM sales
GROUP BY GROUPING SETS ((region, product), (region), ());
```

`ROLLUP` строит иерархические итоги, `CUBE` — комбинации измерений.

### Рекурсивные CTE

`WITH RECURSIVE` используется для запросов, в которых результат следующего шага зависит от результата предыдущего.

Типичная форма:

```sql
WITH RECURSIVE tree AS (
    SELECT id, parent_id, 1 AS depth
    FROM nodes
    WHERE parent_id IS NULL

    UNION ALL

    SELECT n.id, n.parent_id, t.depth + 1
    FROM nodes AS n
    JOIN tree AS t ON n.parent_id = t.id
)
SELECT * FROM tree;
```

Рекурсивный CTE состоит из нерекурсивной начальной части и рекурсивной части, объединённых обычно `UNION ALL`.

### Материализация CTE

PostgreSQL может встроить некоторые CTE в основной запрос или материализовать их. `MATERIALIZED` принудительно создаёт промежуточный результат, `NOT MATERIALIZED` разрешает/подталкивает к встраиванию, когда это допустимо.

### Рамки окон

`PARTITION BY` задаёт раздел, `ORDER BY` — порядок, а **frame** определяет, какая часть раздела участвует в вычислении для текущей строки.

```sql
sum(amount) OVER (
    PARTITION BY account_id
    ORDER BY ts
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

Без явной рамки действует рамка по умолчанию, зависящая от наличия `ORDER BY`.

### Индексы

Индекс ускоряет определённые способы поиска ценой дополнительного места и стоимости изменения данных.

Индекс по выражению:

```sql
CREATE INDEX users_lower_email_idx
ON users (lower(email));
```

Он полезен, когда запрос использует то же выражение.

Частичный индекс содержит только строки, удовлетворяющие предикату:

```sql
CREATE INDEX orders_open_idx
ON orders (customer_id)
WHERE status = 'open';
```

### EXPLAIN и EXPLAIN ANALYZE

`EXPLAIN` показывает план, который выбрал планировщик, с оценками стоимости и количества строк.

`EXPLAIN ANALYZE` **выполняет запрос** и добавляет реальные времена и фактическое число строк.

Для изменяющих команд это особенно важно: `EXPLAIN ANALYZE INSERT/UPDATE/DELETE` реально изменит данные, если не выполнять команду внутри транзакции с последующим `ROLLBACK`.

### Изоляция

Уровень изоляции PostgreSQL по умолчанию — `READ COMMITTED`. Каждый оператор видит снимок данных, актуальный на начало этого оператора.

Более строгие уровни повышают гарантии, но могут приводить к конфликтам сериализации и необходимости повторять транзакцию.

Блокировки и MVCC работают совместно: MVCC уменьшает необходимость блокировать чтения, но изменения конкурирующих строк всё равно могут ждать блокировок или конфликтовать.

### ONLY и наследование

При наследовании запрос к родительской таблице обычно включает строки её потомков. `ONLY parent` ограничивает операцию непосредственно родительской таблицей. `ONLY` применяется в контекстах работы с наследуемыми таблицами для выборки и ряда изменяющих/DDL-команд.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 7.2.1.5. Подзапросы LATERAL

- **LATERAL.** Чтобы подзапрос мог ссылаться на столбцы предшествующих элементов FROM. Без LATERAL подзапрос FROM выполняется независимо от соседних элементов; LATERAL разрешает корреляцию с предыдущими элементами.
- **Правила LATERAL.** Подзапрос LATERAL может ссылаться на предшествующие элементы FROM. Раздел 7.2.1.5 описывает коррелированные элементы FROM и примеры LEFT JOIN LATERAL.

### 7.2.1.4. Табличные функции

- **WITH ORDINALITY.** Столбец bigint с нумерацией строк начиная с 1. WITH ORDINALITY добавляет порядковый столбец к результату табличной функции.

### 7.2.4. GROUPING SETS, CUBE и ROLLUP

- **Наборы группирования.** Позволяют вычислять несколько вариантов группировки в одном запросе. Раздел 7.2.4 описывает более сложные операции группировки через наборы группирования.

### 7.8.2. Рекурсивные запросы

- **WITH RECURSIVE.** Позволяет CTE ссылаться на собственный результат через рекурсивную схему вычисления. Раздел 7.8.2 посвящён рекурсивным запросам WITH.
- **Порядок поиска и выявление циклов.** Они записываются через WITH RECURSIVE. В подразделах 7.8.2.1 и 7.8.2.2 отдельно рассматриваются порядок поиска и циклы.

### 3.5. Оконные функции

- **Размещение оконных функций.** В списке SELECT и в ORDER BY. Оконные функции вычисляются после WHERE/GROUP BY/HAVING, поэтому напрямую разрешены в SELECT и ORDER BY.
- **Рамка окна по умолчанию.** Рамка может быть меньше всего раздела. Введение в оконные функции отдельно объясняет рамку окна и её значения по умолчанию.

### 11.7. Индексы по выражениям

- **Индекс по выражению.** Индексирует результат выражения, а не только исходное значение столбца. Глава 11 отдельно рассматривает индексы по выражениям.

### 11.8. Частичные индексы

- **Предикат частичного индекса.** Он содержит записи только для строк, удовлетворяющих условию предиката. Раздел 11.8 описывает индексы, покрывающие подмножество строк.

### 14.1.2. EXPLAIN ANALYZE

- **Фактическое выполнение.** Запрос реально выполняется и выводятся фактические времена/строки вместе с планом. Раздел 14.1.2 описывает выполнение запроса для получения фактических характеристик.
- **Осторожность с командами изменения.** Команда фактически выполняется. Так как ANALYZE реально выполняет оператор, изменяющие команды требуют осторожности.

### 13.2.1. Уровень изоляции Read Committed

- **Уровень по умолчанию.** Глава 13.2.1 рассматривает Read Committed как стандартный уровень PostgreSQL по умолчанию.

### 11. Индексы

- **Составные, выражения, частичные и покрывающие индексы.** Составные индексы. Глава 11 содержит отдельные разделы для этих возможностей.

### 14.1.1. Азы EXPLAIN

- **Scan, Filter и ORDER BY.** Planner может выбрать Seq Scan, Index Scan или Bitmap Scan в зависимости от стоимости. Примеры EXPLAIN показывают выбор между различными scan nodes, Filter и использование порядка индекса.

### 13. Управление конкурентным доступом

- **Изоляция и явные блокировки.** Read Committed, Repeatable Read и Serializable рассматриваются как уровни изоляции. Глава 13 разделяет уровни изоляции, явные блокировки и взаимоблокировки.

### 7.8.3. Материализация общих табличных выражений

- **Материализация CTE.** Документация рассматривает материализацию общих табличных выражений отдельно. Раздел 7.8.3 посвящён материализации CTE и её влиянию на оптимизацию.

### 3.6. Наследование

- **ONLY.** Материал про наследование указывает, что SELECT, UPDATE и DELETE поддерживают ONLY для ограничения родительской таблицей.
