# 9. Системный каталог

## 1. Тема

PostgreSQL описывает собственную структуру через системные каталоги. Таблицы `pg_catalog` хранят метаданные об объектах, OID связывают записи между каталогами, а удобные представления и метакоманды psql скрывают часть внутренней сложности.

Главная модель:

```text
SQL object
   ↓ metadata
pg_catalog tables
   ↓ OID references
другие catalog rows
   ↓
system views / psql \d*
```

# 2. Механизм

## `pg_catalog` и системные таблицы

Системный каталог хранит метаинформацию: сведения о таблицах, столбцах и других объектах PostgreSQL. Каталог доступен через SQL. Клиенты, включая psql и графические инструменты, могут читать его и представлять полученные сведения в более удобной форме. Основной системный каталог PostgreSQL располагается в схеме pg_catalog.

Имена таблиц и представлений системного каталога начинаются с pg_. По этой причине материал не рекомендует использовать такой префикс для собственных объектов. Для столбцов характерен трёхбуквенный префикс, обычно связанный с именем каталога. Материал отдельно отмечает наличие исключений, например oid. Презентация использует pg_database.datname как пример соглашения: префикс столбца обычно соответствует имени системного каталога.

Практика занятия непосредственно предлагает исследовать pg_class, pg_tables и полный список схем, используя средства просмотра каталога. Хотя системные каталоги являются таблицами, документация прямо предупреждает, что вручную изменять их обычно не следует. Для изменения объектов предназначены SQL-команды. Системный каталог является рабочей частью PostgreSQL, а не просто отчётом. SQL-команды создания и изменения объектов приводят к соответствующим изменениям метаданных каталога.

## OID и `reg*`-типы

OID — числовой идентификатор объекта. Документация PostgreSQL 16 описывает oid как четырёхбайтное целое без знака, применяемое в системных таблицах. , что четырёхбайтный oid недостаточно велик, чтобы гарантировать уникальность во всей крупной базе или даже в очень большой отдельной таблице. PostgreSQL предоставляет несколько типов reg*, которые являются псевдонимами oid для определённых категорий системных объектов. Стандартного типа regdatabase в приведённом перечне нет.

Regclass связан с pg_class и позволяет использовать символическое имя отношения вместо самостоятельного поиска его числового OID. Основное назначение типов reg* — удобное преобразование между числовыми идентификаторами и символическими именами системных объектов.

## Общие и локальные каталоги

Большая часть каталога относится к конкретной базе данных. Одновременно существуют общие для всего кластера объекты каталога, одинаково видимые из разных баз. В презентации список баз данных приведён как очевидный пример метаданных, общих для всего кластера.

## Практический ориентир

```bash
SELECT oid, datname FROM pg_database;
SELECT 'public.orders'::regclass::oid;
SELECT oid, relname, relkind FROM pg_class WHERE relname = 'orders';

\dt
\d+ public.orders
\dn
\l
```

# 3. Важные детали

## Представления и `information_schema`

Материал характеризует information_schema как стандартизованное и более переносимое представление, которое при этом не отражает всю специфику PostgreSQL.

## Метакоманды psql

Семейство команд \d предназначено для описания объектов. Для отношения \d показывает столбцы, их типы и дополнительные характеристики, включая связанные индексы и ограничения. Суффикс + используется многими метакомандами psql для расширенного вывода. Для \d+ документация перечисляет дополнительные сведения о таблицах и представлениях. Для ряда команд \d модификатор S включает в вывод системные объекты.

Psql использует собственные шаблоны поиска объектов. Без шаблона обычно показываются видимые объекты, тогда как *.* позволяет охватить объекты во всех схемах текущей базы. Метакоманда \dn выводит список схем. Она также поддерживает шаблон, S и расширенный вариант +. Семейство команд \d содержит специализированные варианты для разных типов объектов. \dn относится к схемам, а не к функциям.

Ключ -E соответствует включению ECHO_HIDDEN. В таком режиме psql показывает запросы, которые генерируют его метакоманды. Это непосредственно позволяет выполнить практическое задание с \d+ pg_views.

# Что запомнить

```text
• системные каталоги — обычные отношения, но изменять их напрямую почти никогда не следует
• OID — внутренний идентификатор объекта; `regclass` и другие `reg*`-типы делают ссылки читаемее
• часть каталогов общая для всего кластера, часть относится к конкретной БД
• `information_schema` переносимее, `pg_catalog` даёт PostgreSQL-специфичные детали
• метакоманды psql в значительной степени строятся поверх системных каталогов
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
