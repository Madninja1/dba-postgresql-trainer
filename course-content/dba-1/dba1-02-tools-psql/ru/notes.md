# 2. Терминальный клиент psql

## 1. Тема

`psql` — основной терминальный клиент PostgreSQL. Для DBA важно уметь не только выполнить SQL, но и управлять подключением, запускать скрипты, пользоваться метакомандами и безопасно задавать параметры соединения.

Главная модель:

```text
shell / script
     ↓
   psql
  ↙    ↘
метакоманды   SQL
(клиент)      (сервер)
```

# 2. Механизм

## Подключение и параметры запуска

В psql параметр -d задаёт базу данных, -U — пользователя, -h — узел, а -p — порт сервера. Если узел не указан, libpq обычно подключается через локальный Unix-domain socket; стандартный порт PostgreSQL — 5432. Если пользователь не указан, psql по умолчанию использует имя пользователя операционной системы. После определения пользователя его имя применяется и как имя базы данных по умолчанию. Команда \conninfo предназначена для вывода информации о текущем подключении. Команда \connect используется для установки нового подключения.

PGHOST соответствует параметру host, PGDATABASE — dbname, PGPORT — port, а PGUSER — user. Эти переменные позволяют задавать значения параметров соединения по умолчанию. Строка файла паролей содержит пять полей в порядке: имя узла, порт, база данных, имя пользователя и пароль. В практической части материала для вывода подробного списка баз данных предлагается использовать команду \l+.

Значение interactive включает описанное поведение только для интерактивных сеансов psql. При выполнении команд из скриптов оно не применяется.

## SQL и метакоманды

Psql является терминальным клиентом PostgreSQL. Он позволяет интерактивно выполнять запросы, получать команды из файлов или аргументов командной строки и предоставляет собственные метакоманды. В psql команда `--help` показывает справку по параметрам запуска; внутри psql команда \? показывает справку по метакомандам, \? variables — по переменным psql, а \h или \help — по SQL-командам. Завершить psql можно метакомандой \q; материал также показывает команды `exit` и `quit` как варианты выхода. Собственные команды psql начинаются с обратной косой черты. Они обрабатываются самим psql, а не сервером как SQL.

В обычном режиме psql отправляет SQL-команду серверу после завершающей точки с запятой. Перевод строки не обязательно завершает оператор, поэтому SQL удобно вводить в несколько строк. Метакоманды с обратной косой чертой обрабатывает сам psql. PROMPT1 отвечает за основное приглашение psql. PROMPT2 выводится при продолжении ввода, например если команда ещё не завершена точкой с запятой или не закрыты кавычки. Метакоманда \timing on включает отображение времени выполнения каждого SQL-оператора. Вызов \timing без параметра переключает текущее состояние.

При ON_ERROR_ROLLBACK=on psql устанавливает неявную точку сохранения перед каждой командой в блоке транзакции. Если команда завершается ошибкой, выполняется откат к этой точке, что позволяет продолжить транзакцию.

## Скрипты и неинтерактивный запуск

Параметр -c, или --command, передаёт psql команду для выполнения. Если используются -c или -f, после обработки заданных команд psql завершается, а не переходит к чтению команд со стандартного ввода. Параметр -f читает команды из файла, может повторяться и сочетаться с -c и по существу близок к метакоманде \i. При наличии -c или -f psql завершается после обработки этих параметров. Параметр --single-transaction оборачивает обработку команд, переданных через -c и -f, в одну транзакцию. При установленном ON_ERROR_STOP ошибка приводит к ROLLBACK вместо завершающего COMMIT.

## Практический ориентир

```bash
psql -h db.example.net -p 5432 -U app -d appdb

\conninfo
\?
\h SELECT
\dt
\d table_name
\q

psql -d appdb -f migration.sql
psql -d appdb -c "SELECT now();"
```

# 3. Важные детали

## Пароли и параметры соединения

Использование PGPASSWORD не рекомендуется по соображениям безопасности, поскольку в некоторых системах переменные окружения процессов могут быть доступны другим пользователям. Документация предлагает вместо этого использовать файл паролей. Первые четыре поля .pgpass допускают символ *, а поиск прекращается на первой подходящей записи. Поэтому более конкретные записи при использовании шаблонов следует располагать раньше. Двоеточие и обратная косая черта экранируются. В Unix файл паролей должен запрещать доступ группе и остальным пользователям. В документации в качестве подходящего варианта указан режим 0600. При менее строгих правах файл игнорируется.

Файл служб соединения `pg_service.conf` связывает имя службы с параметрами соединения. Пользовательский файл по умолчанию называется `~/.pg_service.conf`; службу можно выбрать через `PGSERVICE`, а сам файл имеет формат INI. Одно из назначений механизма — возможность изменять параметры соединения без перекомпиляции приложения.

## Настройка psql

Параметр из файла службы переопределяет соответствующую переменную окружения, но сам может быть переопределён значением, непосредственно указанным в строке подключения. Psql поддерживает переменные PSQL_PAGER и PAGER и настройки \pset pager. PSQL_PAGER имеет приоритет перед PAGER. Постраничник можно отключить. В практической части .psqlrc используется для постоянных пользовательских настроек psql, в том числе через \setenv. Параметр -X, или --no-psqlrc, запрещает чтение системного и пользовательского стартовых файлов psql.

# Что запомнить

```text
• `-d/-U/-h/-p` задают database/user/host/port
• метакоманды начинаются с `\` и выполняются самим psql
• `-c` и `-f` удобны для автоматизации и завершают psql после обработки
• `PGPASSWORD` нежелателен; для пароля лучше `.pgpass` с корректными правами
• `\conninfo`, `\?`, `\h` и `\connect` — базовый набор администратора
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
