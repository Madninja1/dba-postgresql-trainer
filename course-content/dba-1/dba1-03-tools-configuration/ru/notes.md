# 3. Конфигурация сервера

## 1. Тема

PostgreSQL имеет многоуровневую систему параметров. Одно и то же имя параметра может получить значение из файла, `ALTER SYSTEM`, настроек базы/роли или текущего сеанса; итог определяется контекстом параметра и приоритетом источника.

Главная модель:

```text
defaults
  ↓
postgresql.conf / include
  ↓
postgresql.auto.conf (ALTER SYSTEM)
  ↓
ALTER DATABASE / ALTER ROLE
  ↓
SET в сеансе
  ↓
текущее значение
```

# 2. Механизм

## Параметры и контексты

Если параметр определён несколько раз, действует последнее прочитанное определение. Поэтому порядок подключаемых конфигурационных файлов имеет значение. Конспект различает два представления: pg_file_settings показывает содержимое файлов конфигурации, а pg_settings — действующие значения параметров. Документация перечисляет пять типов параметров: логический, строковый, целое число, число с плавающей точкой и перечисление.

Для строки параметров подключения libpq предусмотрены два формата: последовательность пар ключ=значение и URI подключения. В формате key/value каждый параметр задаётся как ключ=значение. Пробелы вокруг знака равенства необязательны, а значение с пробелом можно заключить в одинарные кавычки. Основная форма URI имеет вид postgresql://[пользователь@][сервер][/база_данных][?параметры]. В качестве схемы также допускается postgres://.

Libpq поддерживает несколько узлов как в URI, так и в формате ключ=значение. Адреса перебираются последовательно до успешного подключения. Если соединение установлено, но аутентификация завершилась ошибкой, остальные узлы уже не перебираются. Практика предлагает намеренно сделать ошибку в подключаемом файле с max_connections, убедиться, что сервер не запускается, проверить журнал сообщений, затем исправить ошибку и снова запустить сервер.

## Файлы конфигурации

Основным файлом конфигурации является postgresql.conf. Он содержит значения параметров сервера и считывается при запуске PostgreSQL. Postgresql.conf является основным серверным конфигурационным файлом и допускает подключение дополнительных файлов. Для применения изменений конфигурацию перечитывают, однако часть параметров воспринимается только при запуске сервера. Расположение основного файла конфигурации отражается параметром config_file. Конспект отдельно предлагает использовать его значение для определения фактического пути к postgresql.conf.

PostgreSQL поддерживает include, include_if_exists и include_dir. include_dir позволяет разбивать конфигурацию на несколько .conf-файлов, которые обрабатываются в определённом порядке имён. Postgresql.auto.conf предназначен для настроек ALTER SYSTEM, располагается в PGDATA и считывается после postgresql.conf. Конспект подчёркивает, что вручную его редактировать не следует.

## `ALTER SYSTEM` и перезагрузка

Перечитывание конфигурации может быть инициировано через pg_ctl reload, SQL-функцию pg_reload_conf() или сигнал SIGHUP главному серверному процессу. Это не означает, что параметры, действующие только после старта, применятся без перезапуска. ALTER SYSTEM является SQL-интерфейсом для глобальных параметров и изменяет postgresql.auto.conf. Команда работает с файловой системой и не может быть помещена в блок транзакции. Новое значение применяется после перечитывания конфигурации либо после перезапуска для параметров, воспринимаемых только при старте. Документация позволяет передавать серверу параметры через postgres -c; такие значения имеют более высокий приоритет, чем настройки из файлов и ALTER SYSTEM. Для отдельного сеанса libpq можно использовать PGOPTIONS, что не влияет на другие сеансы.

## Практический ориентир

```bash
SHOW work_mem;
SET work_mem = '64MB';
SET LOCAL work_mem = '128MB';

ALTER SYSTEM SET shared_buffers = '2GB';
SELECT pg_reload_conf();

ALTER DATABASE appdb SET work_mem = '32MB';
ALTER ROLE analyst SET statement_timeout = '30s';
```

# 3. Важные детали

## Настройки базы, роли и сеанса

ALTER SYSTEM RESET удаляет настройку указанного параметра из postgresql.auto.conf. Для удаления всех параметров, заданных таким способом, существует ALTER SYSTEM RESET ALL. В текущем сеансе значения можно менять командой SET или функцией set_config, а читать командой SHOW или функцией current_setting. Такие изменения не означают редактирование серверного файла postgresql.conf. В материале различаются настройки до конца сеанса и до конца транзакции. SET LOCAL ограничивает изменение текущей транзакцией.

Значения, настроенные через ALTER DATABASE и ALTER ROLE, применяются при новом подключении. Они не изменяют автоматически уже работающие сеансы.

# Что запомнить

```text
• не каждый параметр можно менять на лету: часть требует reload, часть restart
• `ALTER SYSTEM` пишет в `postgresql.auto.conf`, который перекрывает `postgresql.conf`
• `ALTER DATABASE` и `ALTER ROLE` задают defaults для новых сеансов
• `SET` меняет текущий сеанс, `SET LOCAL` — текущую транзакцию
• `pg_settings` показывает текущее значение, источник и контекст параметра
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
