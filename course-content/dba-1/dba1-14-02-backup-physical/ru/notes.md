# 18. Физическое резервное копирование и восстановление

## 1. Тема

Физическая резервная копия сохраняет файлы всего кластера. Для работающего сервера одной копии файлов недостаточно: согласованность достигается базовой копией вместе с WAL, который позволяет воспроизвести изменения до нужного состояния.

Главная модель:

```text
primary cluster
   ├─ pg_basebackup → base backup
   └─ WAL → archive / pg_receivewal

restore:
base backup + WAL
       ↓
recovery
       ↓
consistent cluster
```

---

# 2. Механизм

## Холодная и горячая копия

Физическое копирование работает с файлами кластера, а не с логическим описанием отдельных SQL-объектов. Смысл холодной копии состоит в копировании остановленного кластера, поэтому файлы в процессе не изменяются. Для горячего физического резервирования в конспекте используется pg_basebackup.

Горячая копия создаётся на работающем сервере, поэтому для её согласованности необходимы журнальные записи, относящиеся ко времени копирования. Восстановление физического кластера состоит в воспроизведении записей WAL поверх исходной базовой копии. Связку базовой физической копии и последующего воспроизведения WAL: объекты, созданные после копии, должны появиться после восстановления.

## `pg_basebackup`

Pg_basebackup создаёт физическую копию и использует инфраструктуру протокола репликации, а не логический экспорт строк. Физические инструменты pg_basebackup и pg_receivewal используют специальный режим протокола репликации. Каждое соответствующее репликационное подключение занимает wal sender, поэтому число разрешённых процессов должно учитывать такие соединения.

## Архивирование WAL

Непрерывное архивирование сочетает базовую копию с последовательно сохраняемыми сегментами WAL. Заполненные сегменты WAL отправляются в отдельный архив командой, заданной в archive_command. Restore_command назван обратной по смыслу archive_command: он доставляет нужные WAL из архива серверу восстановления.

При обычном archive_command в архив попадают завершённые сегменты, поэтому текущий незавершённый сегмент может ещё отсутствовать в архиве.

## Практический ориентир

```bash
pg_basebackup -h primary -D /backup/base -Fp -Xs -P

# на primary
archive_mode = on
archive_command = 'cp %p /archive/%f'

# на восстановленном кластере
restore_command = 'cp /archive/%f %p'
touch recovery.signal
```

# 3. Важные детали

## Восстановление и `restore_command`

При архивировании WAL восстановление начинается с развёртывания базовой физической копии, после чего к ней применяются записи WAL. Материал описывает развёртывание базовой копии, recovery.signal и параметры восстановления как основу запуска recovery.

## `pg_receivewal`

Pg_receivewal устраняет ожидание завершения сегмента: принимает поток WAL через репликационное соединение.

---

# Что запомнить

```text
• физическая копия относится ко всему кластеру, а не к отдельной таблице
• холодная копия проста: кластер должен быть корректно остановлен
• горячая базовая копия требует WAL для получения согласованного состояния
• `archive_command` отправляет WAL в архив, `restore_command` получает его при recovery
• `pg_receivewal` потоково принимает WAL и не ждёт завершения текущего сегмента
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
