# 10. Табличные пространства

## 1. Тема

Табличные пространства позволяют привязать логическое размещение объектов PostgreSQL к каталогам файловой системы. Они полезны для распределения данных по носителям, но не являются механизмом резервного копирования или автоматического балансирования.

Главная модель:

```text
tablespace name
      ↓ pg_tablespace
filesystem directory
      ↓
pg_tblspc/<oid> → symlink
      ↓
relation files
```

# 2. Механизм

## Создание и размещение

Табличное пространство задаёт расположение данных в файловой системе и позволяет размещать разные объекты на разных носителях. Табличные пространства позволяют выбирать физическое хранилище для объектов и тем самым управлять доступным дисковым пространством и характеристиками ввода-вывода. Табличные пространства являются объектами уровня кластера. Одно пространство может использоваться разными базами, а одна база может размещать свои объекты в разных пространствах.

Пользовательское пространство как раз позволяет разместить данные вне основного каталога PGDATA. Указанный каталог должен быть заранее создан, пуст и доступен серверу PostgreSQL. Для пользовательских табличных пространств PostgreSQL создаёт в PGDATA/pg_tblspc символические ссылки на фактические каталоги хранения. Для просмотра списка табличных пространств в psql используется метакоманда \db. Те же сведения можно получать из системного каталога pg_tablespace.

Документация прямо указывает возможность выбирать табличные пространства для таблиц, индексов и целых баз данных. В дополнительной практике указано, что чем меньше соотношение стоимости произвольного чтения к последовательному, тем чаще планировщик может предпочитать индексный доступ последовательному сканированию. Полный жизненный цикл пользовательского пространства: создание, влияние шаблона на новую базу, физическую ссылку в PGDATA и последующее удаление.

## Стандартные tablespace

При инициализации кластера создаются стандартные табличные пространства pg_default и pg_global. Pg_global содержит системные объекты, которые относятся ко всему кластеру, а не к отдельной базе данных. У каждой базы есть пространство по умолчанию. Изначально эту роль обычно выполняет pg_default, но для базы может быть назначено другое пространство.

Если TABLESPACE не указан, новая база наследует табличное пространство копируемой базы-шаблона. Поэтому при обычной конфигурации результатом часто оказывается pg_default. Стандартные пространства находятся непосредственно внутри PGDATA: pg_global в global, а pg_default использует base. Для пользовательских пространств применяются ссылки в pg_tblspc.

## Назначение объектам

Непустое значение default_tablespace используется как неявное TABLESPACE при создании таблиц и индексов, если пространство не задано непосредственно командой. DROP TABLESPACE применяется к пустому пространству. Пока существуют использующие его объекты, пространство удалить нельзя. Синтаксис ALTER TABLESPACE PostgreSQL 16 включает RENAME, OWNER, SET и RESET. Изменение LOCATION этим оператором не предусмотрено.

Для параметров конкретного табличного пространства применяется ALTER TABLESPACE ... SET (...). Именно такой способ предлагается в дополнительной практике. В документации PostgreSQL 16 для ALTER TABLESPACE перечислены seq_page_cost, random_page_cost и effective_io_concurrency.

## Практический ориентир

```bash
CREATE TABLESPACE fastspace LOCATION '/mnt/nvme/pg_ts';

CREATE TABLE events(
    id bigint,
    payload jsonb
) TABLESPACE fastspace;

CREATE INDEX events_id_idx ON events(id) TABLESPACE fastspace;

ALTER TABLE events SET TABLESPACE pg_default;
```

# 3. Важные детали

## Временные объекты

Temp_tablespaces предназначен для временных объектов и файлов. Несколько пространств позволяют распределять соответствующую нагрузку.

# Что запомнить

```text
• tablespace — логическое имя, указывающее на физический каталог
• `pg_default` хранит обычные объекты, `pg_global` — общекластерные системные отношения
• таблицу и её индекс можно размещать в разных tablespace
• каталог tablespace должен существовать и иметь правильного владельца
• tablespace не делает данные независимыми от остального кластера
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
