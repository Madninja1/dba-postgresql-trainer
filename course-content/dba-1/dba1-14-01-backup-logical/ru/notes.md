# 17. Логическое резервное копирование

## 1. Тема

Логическая резервная копия описывает объекты и данные на уровне SQL, поэтому может быть выборочной и переносимой между совместимыми серверами. Основные инструменты — `COPY`, `pg_dump`, `pg_restore` и `pg_dumpall`.

Главная модель:

```text
database objects/data
       ↓ pg_dump
 SQL script OR archive
       ↓
psql OR pg_restore
       ↓
restored database
```

---

# 2. Механизм

## `COPY` и `\copy`

Логическое резервирование работает на уровне объектов, их определений и данных, в отличие от физического копирования файлов кластера. COPY используется для обмена табличными данными с файлами или потоками, а не для физической копии PGDATA. SQL COPY выполняется сервером, поэтому файл должен быть доступен серверному процессу PostgreSQL.

Главное различие касается того, на какой стороне открывается файл: сервером при COPY или клиентом при \copy. SQL-дамп уже состоит из команд SQL, поэтому для восстановления его выполняют через клиент PostgreSQL.

## `pg_dump`

В занятии pg_dump представлен как основной инструмент логического резервирования одной базы данных. SQL-вывод и специальные архивные форматы, а также возможность выбирать выгружаемые таблицы, схемы, DDL или данные. В отличие от pg_dump с его архивными форматами, pg_dumpall формирует SQL-скрипт для последующего выполнения.

Возможность отдельно сохранить глобальные объекты, а базы резервировать через pg_dump. Pg_dumpall выдаёт SQL-скрипт, поэтому его восстановление выполняется исполнением этого скрипта.

## Практический ориентир

```bash
# SQL-дамп
pg_dump appdb > appdb.sql
createdb -T template0 appdb_restore
psql -d appdb_restore -f appdb.sql

# custom archive
pg_dump -Fc -f appdb.dump appdb
pg_restore -d appdb_restore -j 4 appdb.dump

# глобальные объекты
pg_dumpall --globals-only > globals.sql
```

---

# 3. Важные детали

## Восстановление

Преимущество архивного формата состоит в наличии оглавления, позволяющего выбирать объекты при восстановлении и использовать параллельную работу. Создать целевую базу из template0 перед восстановлением. Архивный формат с оглавлением позволяет pg_restore выбирать нужные объекты уже после создания резервной копии.

## Глобальные объекты и `pg_dumpall`

Дамп отдельной базы не является полной копией всех глобальных объектов кластера, поэтому зависимости вроде ролей и tablespace должны существовать. Pg_dumpall последовательно выгружает базы кластера и сохраняет информацию, относящуюся ко всему кластеру. Pg_dumpall подключается к базам кластера и должен иметь достаточные права для чтения сохраняемых объектов.

# Что запомнить

```text
• `COPY` открывает файл на стороне сервера, `\copy` — на стороне клиента psql
• `pg_dump` сохраняет одну БД и умеет выбирать объекты
• SQL-дамп восстанавливается через psql, архивные форматы — через pg_restore
• архивный формат позволяет выбирать объекты и использовать параллельное восстановление
• роли и tablespaces — глобальные объекты; их надо резервировать отдельно или через pg_dumpall
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
