# 8. Базы данных и схемы

## 1. Тема

Экземпляр PostgreSQL обслуживает несколько баз данных. Внутри каждой базы объекты организованы по схемам; шаблонные базы определяют начальное содержимое новых БД, а `search_path` управляет разрешением неквалифицированных имён.

Главная модель:

```text
cluster
├─ template0
├─ template1
├─ postgres
└─ appdb
    ├─ pg_catalog
    ├─ public
    ├─ app
    └─ pg_temp_*
```

# 2. Механизм

## Базы и шаблоны

При инициализации кластера создаются три базы: postgres, template0 и template1. Остальные базы впоследствии создаются клонированием существующей базы. Template1 является стандартным шаблоном CREATE DATABASE, template0 сохраняется как чистый исходный шаблон и полезен, в частности, при восстановлении дампа `pg_dump` в базу с исходными настройками локали/кодировки, а postgres предназначена в том числе для обычного подключения к кластеру. CREATE DATABASE реализовано как копирование существующей базы. Стандартным шаблоном является template1.

Template0 сохраняет первоначальное содержимое и позволяет получить чистую базу. Это полезно для восстановления дампа и для создания базы с отличающимися параметрами кодировки и локали. Для копирования базы-шаблона существующие подключения к ней должны быть закрыты. При наличии других сеансов CREATE DATABASE сообщает об ошибке. `postgres.bki` — файл начальной загрузки, из которого сервер получает команды и исходные данные для формирования системных каталогов на этапе инициализации.

В `pg_database` флаг `datistemplate` означает, что базу разрешено использовать как публичный шаблон пользователям с правом `CREATEDB`; `datallowconn` управляет возможностью новых подключений. Сброс `datallowconn` запрещает новые подключения, но сам по себе не завершает уже существующие.

## Схемы и `search_path`

Схема — пространство имён внутри одной базы. Она используется для логической организации объектов и предотвращения конфликтов имён. Клиент подключается к одной базе данных, но внутри неё может обращаться к объектам различных схем. Search_path относится к схемам текущей базы. Для неквалифицированного имени PostgreSQL последовательно ищет объект в доступных схемах фактического пути.

Если команда создания не содержит квалифицированного имени, PostgreSQL использует первую пригодную для создания объектов схему из search_path. Стандартный search_path равен "$user", public. Специальный компонент $user подставляет имя текущего пользователя при наличии соответствующей доступной схемы. Имя вида схема.объект является квалифицированным: схема определяется непосредственно указанным квалификатором.

Pg_catalog содержит системные каталоги PostgreSQL, а information_schema предоставляет другое, стандартизованное SQL-представление метаданных. Pg_catalog всегда участвует в поиске. Если она не указана явно, PostgreSQL просматривает её перед обычными элементами пути. Материал отдельно отмечает, что значение параметра search_path и фактически используемый путь могут различаться. current_schemas(true) показывает путь с учётом неявных схем.

Права схемы и права её объектов разделены. USAGE разрешает использование пространства имён, а CREATE — создание объектов; права на конкретные таблицы и другие объекты назначаются отдельно. При неквалифицированном имени схемы просматриваются слева направо. Поэтому для приоритета пользовательской схемы она должна предшествовать app.

## Временные объекты

Временные таблицы имеют сеансовое или транзакционное время жизни. Они не нуждаются в восстановлении после сбоя и используют локальные временные буферы процесса вместо общего буферного кеша. Фактическая временная схема имеет имя вида pg_temp_N. Универсальное имя `pg_temp` ссылается на временную схему именно текущего сеанса. Каждый сеанс получает собственную временную схему. Даже если `pg_temp` явно не записан в `search_path`, временная схема неявно просматривается раньше остальных схем для отношений и типов; псевдоним `pg_temp` разрешается в неё. Объекты удаляются по окончании сеанса, а схема может использоваться повторно.

`temp_buffers` задаёт максимальный объём локальных буферов для временных таблиц одного сеанса. Эти буферы не используются обычными постоянными таблицами. В PostgreSQL 16 стандартное значение — 8 MB. Стандартное значение temp_buffers равно 8 MB. Четырёхкратное значение составляет 32 MB; его можно установить для базы через ALTER DATABASE ... SET.

## Практический ориентир

```bash
CREATE DATABASE appdb TEMPLATE template0;

CREATE SCHEMA app;
SET search_path = app, public;
CREATE TABLE orders(id bigint);

CREATE TEMP TABLE stage(id bigint);
SHOW search_path;
```

# 3. Важные детали

## Параметры базы

ALTER DATABASE ... SET задаёт сеансовое значение параметра по умолчанию на уровне конкретной базы. Оно начинает действовать для новых подключений.

## Границы базы данных

Обычный клиентский сеанс подключён ровно к одной базе данных. Схемы и `search_path` работают внутри этой базы; обратиться обычным SQL-именем к таблице другой базы того же кластера нельзя.

# Что запомнить

```text
• соединение PostgreSQL всегда устанавливается с конкретной базой данных
• `template1` обычно используется как шаблон CREATE DATABASE, `template0` сохраняют как чистую основу
• схемы — пространства имён внутри одной БД
• `search_path` влияет и на удобство, и на безопасность разрешения имён
• временные объекты принадлежат сеансу и живут в временной схеме
```

Перед тестом полезно не просто узнавать названия команд, а уметь объяснить, **какую задачу решает механизм, на каком уровне он работает и какие ограничения у него есть**.
