# Initial — основы PL/pgSQL

## 1. Тема

Тема посвящена PL/pgSQL — серверному процедурному языку PostgreSQL, который дополняет SQL переменными, блоками, управляющими конструкциями, обработкой ошибок и динамическим выполнением.

## 2. Механизм

PL/pgSQL — процедурный язык PostgreSQL для функций, процедур и триггеров. Он добавляет к SQL переменные, условия, циклы и обработку результатов внутри сервера.

### Структура блока

Базовая форма:

```sql
DECLARE
    total integer := 0;
BEGIN
    -- операторы
END;
```

`DECLARE` необязателен. `BEGIN ... END` — блок PL/pgSQL, а не SQL-команды начала/фиксации транзакции.

Все обычные локальные переменные объявляются в `DECLARE`.

### Переменные

```sql
DECLARE
    counter integer := 0;
    name text;
    started_at CONSTANT timestamptz := now();
```

Если `DEFAULT`/`:=`/`=` не заданы, переменная получает `NULL`.

Разрешены присваивания:

```sql
counter := counter + 1;
counter = counter + 1;
```

### Параметры функций

Параметры доступны по имени, если они названы в `CREATE FUNCTION`, и как `$1`, `$2`, ... .

```sql
CREATE FUNCTION add_tax(subtotal numeric)
RETURNS numeric
LANGUAGE plpgsql AS $$
BEGIN
    RETURN subtotal * 1.2;
END;
$$;
```

### Условия

Основные формы:

```sql
IF condition THEN
    ...
ELSIF other_condition THEN
    ...
ELSE
    ...
END IF;
```

Также поддерживается `CASE`.

### Циклы

PL/pgSQL имеет несколько вариантов:

- `LOOP ... END LOOP`;
- `WHILE`;
- `FOR i IN ...` по диапазону;
- `FOR row IN query` по строкам запроса;
- `FOREACH` по массиву.

### SELECT INTO

Чтобы получить одну строку запроса в переменные:

```sql
SELECT id, name
INTO user_id, user_name
FROM users
WHERE login = p_login;
```

Без `STRICT` берётся первая строка; если строк нет, целевые переменные получают `NULL`.

### PERFORM

Если результат запроса не нужен, но важен сам вызов/побочный эффект:

```sql
PERFORM refresh_cache();
```

Обычный `SELECT`, возвращающий строки и не имеющий `INTO`, в PL/pgSQL использовать для этого нельзя.

### FOUND

`FOUND` — специальная boolean-переменная. При входе в функцию она `false`. Различные операторы меняют её, например `SELECT INTO`, `PERFORM`, DML и циклы.

```sql
SELECT * INTO rec FROM users WHERE id = p_id;
IF NOT FOUND THEN
    RAISE EXCEPTION 'user not found';
END IF;
```

### RETURN, RETURN NEXT, RETURN QUERY

Для одиночного результата:

```sql
RETURN value;
```

Для set-returning function:

```sql
RETURN NEXT row_value;
RETURN QUERY SELECT ...;
```

`RETURN NEXT` и `RETURN QUERY` добавляют строки к результирующему набору; окончательный `RETURN` завершает функцию.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 43.1. Обзор

- **Назначение PL/pgSQL.** Для создания серверных функций, процедур и триггеров с управляющими структурами поверх SQL. Обзор PL/pgSQL описывает процедурный язык, который расширяет SQL управляющими конструкциями и выполняется на сервере.
- **Возможности PL/pgSQL.** Создание функций, процедур и триггеров. Обзор перечисляет эти цели и преимущества языка.

### 43.2. Структура PL/pgSQL

- **DECLARE / BEGIN / END.** Необязательный DECLARE и обязательный BEGIN .. END. PL/pgSQL — блочно-структурированный язык с DECLARE и выполняемой секцией BEGIN/END.
- **Правила блока.** Операторы обычно завершаются `;`. Документация отдельно предупреждает не путать блочные BEGIN/END с управлением транзакциями.

### 43.3. Объявления

- **DECLARE.** В секции DECLARE. Все переменные блока, кроме специальных автоматически создаваемых, объявляются в DECLARE.
- **Начальное значение переменной.** Если DEFAULT отсутствует, переменная инициализируется SQL-значением NULL.
- **Синтаксис переменной.** DEFAULT или :=/= для начального значения. Общий синтаксис объявления включает эти модификаторы.

### 43.5.1. Присваивания

- **переменная := выражение.** := и =. Документация допускает `:=` и `=` для присваивания переменным.

### 43.5.2. Выполнение команд SQL

- **PERFORM.** Использовать PERFORM. PERFORM выполняет запрос и отбрасывает его результат.
- **PERFORM и FOUND.** Выполняет запрос и отбрасывает результат. Раздел основных операторов описывает PERFORM и влияние на FOUND.

### 43.5.3. Выполнение команды, возвращающей одну строку

- **SELECT .. INTO.** Использовать SELECT .. INTO цель. PL/pgSQL использует INTO для захвата результата SQL-команды в record/row/scalar targets.

### 43.5.5. Статус выполнения команды

- **FOUND.** FOUND — специальная boolean-переменная, инициализируемая false при вызове функции.
- **Операторы, меняющие FOUND.** SELECT INTO. Документация перечисляет операторы, меняющие FOUND, и отдельно отмечает, что EXECUTE его не меняет.

### 43.6.1.1. RETURN

- **RETURN выражение.** RETURN выражение прекращает выполнение функции и возвращает значение.

### 43.3.1. Объявление параметров функции

- **$1 и ALIAS.** Их можно обозначать как $1, $2 и т. д. Раздел 43.3.1 описывает цифровые имена и псевдонимы параметров.

### 43.6.4. Условные операторы

- **IF и CASE.** IF .. THEN. Раздел управляющих структур перечисляет формы IF и CASE.

### 43.6.5–43.6.7

- **Циклы.** LOOP. Глава 43.6 перечисляет простые циклы, цикл по результату и FOREACH.

### 43.6.1.2. RETURN NEXT и RETURN QUERY

- **Накопление результата.** Они добавляют строки в результирующее множество. Раздел 43.6.1.2 описывает накопление результирующего множества.
