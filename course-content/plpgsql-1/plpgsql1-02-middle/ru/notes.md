# Middle — уверенный PL/pgSQL

## 1. Тема

Тема посвящена PL/pgSQL — серверному процедурному языку PostgreSQL, который дополняет SQL переменными, блоками, управляющими конструкциями, обработкой ошибок и динамическим выполнением.

## 2. Механизм

Этот уровень — типы, строгий `INTO`, динамический SQL, диагностика, исключения и курсоры.

### %TYPE

`%TYPE` наследует тип существующего столбца или переменной:

```sql
DECLARE
    v_user_id users.id%TYPE;
```

Если тип столбца позже изменится, функцию часто не придётся переписывать.

### %ROWTYPE

`%ROWTYPE` создаёт переменную с фиксированной структурой строки таблицы/представления:

```sql
DECLARE
    u users%ROWTYPE;
```

Поля доступны как `u.id`, `u.name` и т. д.

### RECORD

`RECORD` не имеет заранее заданной структуры. Она определяется строкой, присвоенной во время выполнения.

```sql
DECLARE
    r record;
BEGIN
    SELECT * INTO r FROM users LIMIT 1;
END;
```

До первого присваивания обращаться к полям `record` нельзя.

### INTO STRICT

```sql
SELECT *
INTO STRICT u
FROM users
WHERE login = p_login;
```

`STRICT` требует **ровно одну строку**:

- 0 строк → `NO_DATA_FOUND`;
- больше 1 строки → `TOO_MANY_ROWS`.

Без `STRICT` берётся первая строка, а при отсутствии строк присваивается `NULL`.

### Динамический EXECUTE

Если меняется сам текст SQL, например имя таблицы, используется `EXECUTE`:

```sql
EXECUTE 'SELECT count(*) FROM ' || quote_ident(tabname)
INTO cnt;
```

Для значений данных предпочтительно использовать параметры `USING`:

```sql
EXECUTE 'SELECT count(*) FROM users WHERE status = $1'
INTO cnt
USING wanted_status;
```

Параметры `$1`, `$2` заменяют **значения**, но не имена таблиц/столбцов.

Для идентификаторов удобно:

```sql
EXECUTE format('SELECT count(*) FROM %I WHERE id = $1', tabname)
INTO cnt
USING wanted_id;
```

`%I` — идентификатор, `%L` — SQL-литерал.

### Диагностика

После команды можно получить сведения:

```sql
GET DIAGNOSTICS affected = ROW_COUNT;
```

`ROW_COUNT` — число обработанных строк последней SQL-командой.

### EXCEPTION

Обработчик ошибок задаётся внутри блока:

```sql
BEGIN
    ...
EXCEPTION
    WHEN unique_violation THEN
        ...
    WHEN OTHERS THEN
        ...
END;
```

При ошибке изменения базы, выполненные внутри блока с `EXCEPTION`, откатываются до начала этого блока, а локальные переменные сохраняют свои значения.

### RAISE

Сообщения и ошибки:

```sql
RAISE NOTICE 'id = %', v_id;
RAISE WARNING 'unexpected value';
RAISE EXCEPTION 'user % not found', p_login;
```

Можно задавать SQLSTATE и дополнительные поля через `USING`.

### Курсоры

Курсорная переменная имеет тип `refcursor`.

Основные операции:

- `OPEN`;
- `FETCH` / `MOVE`;
- `CLOSE`;
- цикл `FOR ... IN cursor`.

Курсоры полезны для пошаговой обработки набора строк, хотя обычный `FOR row IN SELECT` часто проще.

### RETURN QUERY

`RETURN QUERY` добавляет весь результат запроса к набору, возвращаемому функцией. Он может применяться несколько раз вместе с `RETURN NEXT`.

## 3. Важные детали и покрытие тестов

Ниже собраны детали, которые проверяются вопросами этой темы. Они сгруппированы по разделам исходной документации, чтобы их можно было связывать с механизмом, а не запоминать как отдельный список ответов.

### 43.3.3. Наследование типов данных

- **%TYPE.** Наследует тип данных указанной переменной или столбца. `%TYPE` позволяет не дублировать тип и автоматически следовать его изменению.

### 43.3.4. Типы кортежей

- **%ROWTYPE.** Тип строки существующей таблицы или представления. `table%ROWTYPE` объявляет переменную-кортеж со структурой строки таблицы/представления.

### 43.3.5. Тип record

- **RECORD.** RECORD не имеет заранее фиксированной структуры и получает её при присваивании строки. Переменная RECORD приобретает структуру динамически и до первого присваивания её поля недоступны.

### 43.5.3. Выполнение команды, возвращающей одну строку

- **INTO STRICT.** Команда должна вернуть ровно одну строку, иначе будет ошибка. STRICT приводит к NO_DATA_FOUND при 0 строк и TOO_MANY_ROWS при более чем одной.
- **INTO без STRICT.** Берётся первая строка результата. Без STRICT остальные строки после первой отбрасываются; наличие строки можно проверить через FOUND.
- **NO_DATA_FOUND / TOO_MANY_ROWS.** NO_DATA_FOUND при отсутствии строк. STRICT требует ровно одну строку.

### 43.5.4. Выполнение динамически формируемых команд

- **EXECUTE.** Для выполнения динамически сформированной команды. EXECUTE принимает строку команды и строит план при каждом выполнении.
- **EXECUTE .. USING.** Через параметры $1, $2 и предложение USING. USING сохраняет типы данных и исключает необходимость текстового quoting для значений.
- **EXECUTE INTO USING.** Текст команды вычисляется как text. Динамический EXECUTE отличается отсутствием кеширования плана и поддерживает INTO/USING.
- **format / quote_ident / quote_nullable.** format с %I для идентификаторов. Документация динамического SQL описывает format/quote_* и отдельно рекомендует USING для data values.

### 43.5.5. Статус выполнения команды

- **GET DIAGNOSTICS ROW_COUNT.** Число строк, обработанных последней SQL-командой. ROW_COUNT имеет тип bigint и возвращает число обработанных строк.

### 43.6.8. Обработка ошибок

- **EXCEPTION.** Блок с EXCEPTION перехватывает заданные условия ошибок.
- **EXCEPTION WHEN.** Если оператор в блоке вызывает ошибку, последующие операторы этого блока пропускаются. Раздел обработки ошибок описывает семантику блока и откат изменений.

### 43.7.1. Объявление курсорных переменных

- **refcursor.** Курсорные переменные в PL/pgSQL имеют тип refcursor.

### 43.3.3–43.3.4

- **%TYPE и %ROWTYPE.** %TYPE наследует тип столбца/переменной. Обе конструкции связывают объявления PL/pgSQL со схемой данных.

### 43.7. Использование курсоров

- **OPEN/FETCH/MOVE/CLOSE.** OPEN. Глава 43.7 разбирает открытие, выборку, перемещение и закрытие курсоров.

### 43.6.1.2. RETURN NEXT и RETURN QUERY

- **RETURN QUERY / EXECUTE.** Добавляет строки результата запроса в результирующее множество функции. RETURN QUERY накапливает строки и выполнение продолжается.

### 43.9.1. Вывод сообщений и ошибок

- **RAISE.** Используется для сообщений и ошибок. Глава 43.9 посвящена сообщениям и ошибкам PL/pgSQL.
