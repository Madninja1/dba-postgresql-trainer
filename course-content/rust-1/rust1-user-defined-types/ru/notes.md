# Шаг 5. Пользовательские типы

## 1. Тема

В Rust основные средства создания собственных типов предметной области — **структуры (`struct`)** и **перечисления (`enum`)**.

```text
struct
→ одно значение состоит из набора связанных данных

enum
→ значение может быть одним из нескольких вариантов
```

Структуры позволяют объединять связанные поля под одним типом. Перечисления позволяют описывать тип через набор допустимых вариантов, причём каждый вариант может хранить собственные данные. На этих механизмах строятся типы вроде `Option<T>`, а для обработки вариантов используются `match` и `if let`. Язык программирования Rust(2)

---

# 2. Механизм

## Структуры `struct`

Структура объединяет несколько связанных значений в новый тип.

```rust
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}
```

Каждая пара:

```text
имя: тип
```

называется **полем**.

Создание экземпляра:

```rust
let user = User {
    active: true,
    username: String::from("daniel"),
    email: String::from("mail@example.com"),
    sign_in_count: 1,
};
```

В отличие от tuple, поля структуры имеют имена, поэтому их смысл не зависит от позиции. Язык программирования Rust(2)

Доступ к полю:

```rust
user.email
```

---

## Изменяемая структура

Для изменения поля весь экземпляр должен быть объявлен `mut`:

```rust
let mut user = User {
    active: true,
    username: String::from("daniel"),
    email: String::from("old@example.com"),
    sign_in_count: 1,
};

user.email = String::from("new@example.com");
```

Нельзя отдельно объявить одно поле изменяемым, оставив сам экземпляр immutable.

```text
let mut user
      ↓
поля экземпляра можно менять
```

Язык программирования Rust(2)

---

## Сокращённая инициализация полей

Если имя переменной совпадает с именем поля:

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username,
        email,
        sign_in_count: 1,
    }
}
```

вместо:

```rust
username: username,
email: email,
```

можно написать просто:

```rust
username,
email,
```

Это только сокращённый синтаксис, смысл не меняется. Язык программирования Rust(2)

---

## Обновление структуры `..`

Можно создать новый экземпляр, взяв остальные поля из существующего:

```rust
let user2 = User {
    email: String::from("new@example.com"),
    ..user1
};
```

`..user1` должен стоять после явно заданных полей.

Механизм здесь связан с уже изученным ownership.

Если из `user1` в `user2` переносится поле типа `String`, это может быть **move**:

```text
user1.username: String
        ↓
      move
        ↓
user2.username
```

После этого использование всего `user1` может стать недопустимым.

Если же копируются только поля типа `Copy`, например `bool` или `u64`, соответствующие значения копируются. Язык программирования Rust(2)

Это важная связь:

```text
struct update syntax
        ↓
не отменяет ownership
        ↓
для каждого поля действуют обычные move/Copy правила
```

---

## Tuple structs

Есть структуры без имён полей:

```rust
struct Color(i32, i32, i32);
struct Point(i32, i32, i32);
```

Создание:

```rust
let black = Color(0, 0, 0);
let origin = Point(0, 0, 0);
```

Несмотря на одинаковые внутренние типы:

```text
Color ≠ Point
```

Это разные пользовательские типы.

Поэтому функция:

```rust
fn f(c: Color)
```

не может принять `Point`.

Доступ к полям похож на tuple:

```rust
black.0
black.1
```

Tuple struct полезен, когда нужен **отдельный тип**, но именовать каждое поле нет необходимости. Язык программирования Rust(2)

---

## Unit-like structs

Структура может вообще не содержать полей:

```rust
struct AlwaysEqual;
```

Создание:

```rust
let subject = AlwaysEqual;
```

Такой тип называется **unit-like struct**, поскольку напоминает тип `()`.

Книга отмечает, что подобная структура полезна, когда нужно определить поведение для типа, но хранить внутри данные не требуется. Язык программирования Rust(2)

---

## Владение полями структуры

В примере `User` используются:

```rust
username: String,
email: String,
```

то есть структура **сама владеет этими данными**.

```text
User
 ├─ owns username
 └─ owns email
```

За счёт этого данные существуют столько, сколько существует сама структура.

Структура может хранить и ссылки на чужие данные, но тогда появляется необходимость описывать **lifetimes**. Книга откладывает этот механизм до главы 10. Язык программирования Rust(2)

Пока практическая модель:

```text
field: String
→ структура владеет строкой

field: &str
→ структура заимствует строку
→ нужны правила lifetime
```

---

# Методы и `impl`

Данные структуры можно дополнить поведением.

Для этого используется блок:

```rust
impl Rectangle {
    ...
}
```

Например:

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}
```

Вызов:

```rust
rect.area()
```

Метод похож на функцию, но связан с конкретным типом и первым параметром получает `self`. Язык программирования Rust(2)

---

## `self`, `&self`, `&mut self`

Книга показывает три варианта отношения метода к экземпляру.

### `&self`

```rust
fn area(&self) -> u32
```

Метод только читает структуру.

`&self` — сокращение:

```rust
self: &Self
```

где `Self` означает тип, для которого написан `impl`.

Для:

```rust
impl Rectangle
```

`Self` означает `Rectangle`.

---

### `&mut self`

Если метод должен изменить экземпляр:

```rust
fn change(&mut self) {
    ...
}
```

Это изменяемое заимствование уже изученного типа:

```text
&mut self
→ метод временно получает изменяемый доступ
→ ownership остаётся у вызывающего кода
```

---

### `self`

Метод может принять:

```rust
fn method(self)
```

Тогда он получает экземпляр во владение.

Книга отмечает, что такой вариант встречается реже и полезен, например, когда метод преобразует значение так, что исходный экземпляр после этого больше не должен использоваться.

Итого:

```text
&self
→ читать

&mut self
→ менять

self
→ забрать ownership
```

---

## Аргументы методов

После `self` метод может принимать обычные параметры:

```rust
impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width
            && self.height > other.height
    }
}
```

Вызов:

```rust
rect1.can_hold(&rect2)
```

`self` соответствует `rect1`, а `other` — `rect2`.

---

## Автоматическое заимствование при вызове метода

При:

```rust
object.method()
```

Rust автоматически добавляет подходящую форму:

```text
&
&mut
*
```

чтобы получатель соответствовал сигнатуре метода.

Поэтому при методах обычно не нужно вручную писать сложные комбинации разыменования и заимствования.

Rust смотрит на первый параметр метода:

```text
&self     → чтение
&mut self → изменение
self      → получение ownership
```

и подбирает нужный способ вызова.

---

# Ассоциированные функции

Все функции внутри `impl` называются **ассоциированными функциями**.

Метод — это ассоциированная функция с параметром `self`.

Можно создать функцию без `self`:

```rust
impl Rectangle {
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}
```

Вызов:

```rust
let square = Rectangle::square(10);
```

То есть:

```text
instance.method()
→ метод экземпляра

Type::function()
→ ассоциированная функция
```

Такие функции часто используются для создания экземпляров.

Книга отдельно отмечает: имя `new` для таких функций распространено, но **не является специальным ключевым словом Rust**. Язык программирования Rust(2)

Можно иметь несколько блоков:

```rust
impl Rectangle {
    fn area(&self) -> u32 { ... }
}

impl Rectangle {
    fn square(size: u32) -> Self { ... }
}
```

Это допустимо и эквивалентно размещению методов в одном подходящем `impl`.

---

# Отладочная печать пользовательских типов

Структура не получает форматирование `Debug` автоматически.

Можно запросить его:

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}
```

После этого доступны:

```rust
println!("{rect:?}");
```

и более развёрнутый формат:

```rust
println!("{rect:#?}");
```

Книга также показывает:

```rust
dbg!(&rect);
```

`dbg!` выводит отладочную информацию в `stderr`, включая файл и строку вызова. Сам `dbg!` возвращает переданное ему значение, поэтому при нежелании передавать ownership можно передать ссылку. Это скорее вспомогательная возможность разработки, чем фундамент модели типов.

# Перечисления `enum`

## Enum как набор вариантов

`enum` определяет тип, который может иметь **одно значение из набора вариантов**.

Простой пример:

```rust
enum IpAddrKind {
    V4,
    V6,
}
```

Значения:

```rust
IpAddrKind::V4
IpAddrKind::V6
```

Оба принадлежат одному типу:

```text
IpAddrKind
```

Основная идея:

```text
struct
→ одновременно содержит набор полей

enum
→ в конкретный момент является одним вариантом
```

---

## Варианты enum могут содержать данные

В Rust каждый вариант может иметь собственную форму данных:

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}
```

Здесь:

```text
Quit
→ данных нет

Move
→ именованные поля

Write
→ String

ChangeColor
→ три i32
```

Все они по-прежнему имеют один тип:

```text
Message
```

Язык программирования Rust(2)

Это позволяет выразить модель:

```text
Message =
    Quit
    ИЛИ Move(x, y)
    ИЛИ Write(text)
    ИЛИ ChangeColor(r, g, b)
```

Вместо создания нескольких отдельных структур у вариантов есть общий тип `Message`.

---

## Методы для enum

Как и для структуры, для перечисления можно написать:

```rust
impl Message {
    fn call(&self) {
        ...
    }
}
```

И затем:

```rust
message.call();
```

То есть `impl` относится не только к `struct`: enum тоже может иметь методы.

---

# `Option<T>`

Один из ключевых стандартных enum:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Он описывает:

```text
значение есть
→ Some(T)

значения нет
→ None
```

`Option<T>`, `Some` и `None` входят в prelude, поэтому писать:

```rust
Option::Some(...)
```

обычно не требуется.

Примеры:

```rust
let number = Some(5);
let letter = Some('a');

let missing: Option<i32> = None;
```

В последнем случае тип нужно указать, потому что из одного `None` компилятор не может определить, каким был бы тип внутри `Some`. Язык программирования Rust(2)

---

## Почему `Option<T>` важен

`T` и `Option<T>` — **разные типы**.

Например:

```rust
let x: i8 = 5;
let y: Option<i8> = Some(5);
```

нельзя просто сделать:

```rust
x + y
```

Потому что:

```text
i8 ≠ Option<i8>
```

Перед использованием внутреннего `T` необходимо обработать возможность `None`.

Это заставляет код явно разделять:

```text
Some(value)
→ значение существует

None
→ значения нет
```

Тем самым отсутствие значения представлено в системе типов, а не скрыто внутри обычного значения. Язык программирования Rust(2)

---

# `match`

`match` сопоставляет значение с **шаблонами (patterns)**.

```rust
match value {
    pattern1 => expression1,
    pattern2 => expression2,
}
```

Например:

```rust
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}
```

Rust проверяет шаблоны по порядку и выполняет код первой совпавшей ветви. Сам `match` является выражением, поэтому значение выполненной ветви становится значением всего `match`. Язык программирования Rust(2)

---

## Извлечение данных через pattern

`match` умеет не только определить вариант, но и получить данные внутри него.

Например:

```rust
enum Coin {
    Penny,
    Quarter(UsState),
}
```

Можно написать:

```rust
match coin {
    Coin::Penny => 1,

    Coin::Quarter(state) => {
        println!("{state:?}");
        25
    }
}
```

При совпадении:

```text
Coin::Quarter(UsState::Alaska)
```

шаблон:

```rust
Coin::Quarter(state)
```

привязывает:

```text
state = UsState::Alaska
```

То есть pattern одновременно:

```text
проверяет форму значения
+
извлекает его внутренние данные
```

---

## `Option<T>` + `match`

Типичная обработка:

```rust
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}
```

Для:

```rust
Some(5)
```

шаблон:

```rust
Some(i)
```

извлекает:

```text
i = 5
```

и получается:

```rust
Some(6)
```

Для `None` возвращается `None`.

---

## `match` обязан быть исчерпывающим

Одна из важнейших особенностей:

> `match` должен обработать все возможные варианты.

Это не компилируется:

```rust
match x {
    Some(i) => Some(i + 1),
}
```

если `x` имеет тип `Option<i32>`.

Не обработан:

```rust
None
```

Компилятор обнаружит это.

Для `Option<T>` это особенно важно:

```text
Some(T)
+
None
```

должны быть учтены явно либо покрыты универсальным шаблоном.

---

## Catch-all pattern

Можно обработать конкретные случаи, а остальные собрать в одну ветку:

```rust
match dice_roll {
    3 => add_hat(),
    7 => remove_hat(),
    other => move_player(other),
}
```

`other` совпадёт со всеми оставшимися значениями и привяжет само значение.

Универсальная ветка должна располагаться после специфичных, потому что шаблоны проверяются сверху вниз.

---

## `_` — игнорирование значения

Если значение остальных случаев не требуется:

```rust
match dice_roll {
    3 => add_hat(),
    7 => remove_hat(),
    _ => reroll(),
}
```

`_`:

```text
совпадает с любым значением
+
не привязывает его к переменной
```

Если для остальных случаев вообще ничего делать не нужно:

```rust
match value {
    special => do_something(),
    _ => (),
}
```

`()` означает отсутствие действия/полезного значения.

---

# `if let`

Иногда `match` слишком многословен, если интересует только **один шаблон**.

Например:

```rust
let config = Some(3u8);

match config {
    Some(max) => println!("{max}"),
    _ => (),
}
```

можно сократить:

```rust
if let Some(max) = config {
    println!("{max}");
}
```

Модель:

```text
если value соответствует pattern
        ↓
привязать внутренние значения
        ↓
выполнить блок
```

`if let` игнорирует остальные варианты. Язык программирования Rust(2)

Главный компромисс:

```text
match
→ больше кода
→ проверка полноты всех вариантов

if let
→ короче
→ остальные варианты можно просто проигнорировать
```

---

## `if let ... else`

Можно добавить:

```rust
if let Some(value) = option {
    ...
} else {
    ...
}
```

`else` примерно соответствует универсальной ветке:

```rust
_ => ...
```

в `match`.

# 3. Важные детали

Главная разница между `struct` и `enum`:

```text
struct User {
    name,
    email,
    active
}

одно значение User
содержит все эти поля одновременно
```

А:

```text
enum Message {
    Quit,
    Write(String),
    Move { x, y }
}
```

означает:

```text
конкретный Message
является только одним вариантом
```

---

Типовой подход к моделированию:

```text
"объект имеет несколько характеристик"
→ struct

"значение может находиться в одном
из нескольких состояний/форм"
→ enum
```

Для поведения:

```text
impl Type {
    ...
}
```

Для работы с вариантами:

```text
match
if let
```

---

Важно помнить связь с ownership:

```text
struct {
    field: String
}

→ структура владеет String
```

и:

```rust
let b = Struct {
    ..a
};
```

может переместить non-`Copy` поля из `a`.

Пользовательские типы не обходят правила владения — поля подчиняются тем же правилам `move`, `Copy` и borrowing, что и обычные значения.

# 4. Что запомнить

Минимальная модель `struct`:

```rust
struct User {
    name: String,
    active: bool,
}
```

Экземпляр:

```rust
let user = User {
    name: String::from("Daniil"),
    active: true,
};
```

Доступ:

```rust
user.name
```

Изменение:

```rust
let mut user = ...;
user.active = false;
```

Сокращение:

```rust
User {
    name,
    active,
}
```

Обновление:

```rust
User {
    active: false,
    ..old_user
}
```

При `..old_user` помнить о `move` non-`Copy` полей.

---

Методы:

```rust
impl Type {
    fn read(&self) { }

    fn change(&mut self) { }

    fn consume(self) { }
}
```

Запомнить:

```text
&self
→ читать

&mut self
→ изменять

self
→ забрать ownership
```

Ассоциированная функция:

```rust
impl Rectangle {
    fn square(size: u32) -> Self {
        ...
    }
}
```

Вызов:

```rust
Rectangle::square(10)
```

Различие:

```text
object.method()
Type::function()
```

---

Enum:

```rust
enum Message {
    Quit,
    Write(String),
    Move { x: i32, y: i32 },
}
```

Каждый вариант может содержать свои данные.

`Option<T>`:

```rust
Some(T)
None
```

и:

```text
T ≠ Option<T>
```

Поэтому отсутствие значения нельзя незаметно проигнорировать.

---

`match`:

```rust
match value {
    PatternA => ...,
    PatternB(x) => ...,
}
```

Нужно помнить:

```text
match
→ сопоставляет по pattern
→ может извлекать внутренние данные
→ является выражением
→ обязан покрывать все случаи
```

Универсальные шаблоны:

```rust
other => ...
```

если значение понадобится,

или:

```rust
_ => ...
```

если значение не требуется.

---

`if let`:

```rust
if let Some(value) = option {
    ...
}
```

использовать, когда важен только один вариант.

Главная итоговая схема:

```text
STRUCT
→ какие данные составляют значение?

ENUM
→ каким из вариантов может быть значение?

IMPL
→ какое поведение связано с типом?

MATCH
→ какой вариант получен и что из него извлечь?

OPTION<T>
→ значение существует или отсутствует?
```

После этого шага Rust уже позволяет создавать собственную модель предметной области не только из примитивных типов: данные можно собирать в `struct`, состояния и альтернативы — в `enum`, поведение связывать через `impl`, а варианты безопасно разбирать через `match`.

**Объём конспекта:** примерно **10–12 тыс. символов** с кодом.

**Время переноса в тетрадь:** примерно **60–75 минут**. Основной приоритет при записи: `struct`, `impl/self`, `enum`, `Option<T>`, исчерпывающий `match` и отличие `match` от `if let`.
