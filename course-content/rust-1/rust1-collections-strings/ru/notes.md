# Шаг 7. Коллекции и строки

## 1. Тема

Коллекции стандартной библиотеки позволяют хранить **несколько значений**, причём их размер может быть неизвестен во время компиляции и изменяться во время работы программы. В отличие от массивов и кортежей, данные рассматриваемых коллекций хранятся в куче. Язык программирования Rust(2)

В этой главе три основных типа:

```text
Vec<T>
→ последовательность элементов одного типа

String
→ изменяемая владеющая строка UTF-8

HashMap<K, V>
→ пары ключ → значение
```

Главная связь с предыдущими темами:

```text
коллекции
   ↓
хранят данные
   ↓
следуют обычным правилам
ownership + borrowing
```

---

# 2. Механизм

## `Vec<T>` — динамический список

Вектор хранит последовательность элементов **одного типа**:

```rust
let v = vec![1, 2, 3];
```

Тип:

```text
Vec<i32>
```

В отличие от массива, количество элементов вектора может изменяться.

Пустой вектор:

```rust
let v: Vec<i32> = Vec::new();
```

Здесь тип приходится указать явно, потому что по пустому вектору компилятор не может определить тип элементов.

Если начальные значения уже есть:

```rust
let v = vec![1, 2, 3];
```

тип выводится автоматически. Язык программирования Rust(2)

---

## Добавление элементов

Для изменения нужен `mut`:

```rust
let mut v = Vec::new();

v.push(5);
v.push(6);
v.push(7);
```

После вставок Rust уже может вывести:

```text
Vec<i32>
```

Все элементы одного `Vec<T>` должны иметь один тип.

---

## Получение элемента

Есть два основных способа.

### Индексация

```rust
let v = vec![1, 2, 3, 4, 5];

let third = &v[2];
```

Результат:

```text
&i32
```

Индексация начинается с `0`.

Если индекс недопустим:

```rust
&v[100]
```

программа вызывает `panic`.

---

### `get`

```rust
let third = v.get(2);
```

Результат:

```text
Option<&T>
```

То есть:

```text
существует элемент
→ Some(&value)

элемента нет
→ None
```

Например:

```rust
match v.get(100) {
    Some(value) => println!("{value}"),
    None => println!("Нет элемента"),
}
```

Различие:

```text
v[index]
→ неверный индекс = panic

v.get(index)
→ неверный индекс = None
```

`get` подходит, когда отсутствие элемента является нормальным вариантом работы программы. Язык программирования Rust(2)

---

## Вектор и borrowing

Этот код запрещён:

```rust
let mut v = vec![1, 2, 3, 4, 5];

let first = &v[0];

v.push(6);

println!("{first}");
```

Причина связана не просто с синтаксическим правилом.

Элементы `Vec<T>` расположены последовательно. При `push` может оказаться, что текущего участка памяти больше недостаточно.

Тогда вектор может:

```text
выделить новый участок
        ↓
переместить туда элементы
        ↓
освободить старый участок
```

Старая ссылка:

```text
first → старый участок памяти
```

стала бы недействительной.

Поэтому borrow checker запрещает изменять вектор таким образом, пока активна ссылка на его элемент. Язык программирования Rust(2)

Это важная практическая связь:

```text
ссылка на элемент Vec
        ↓
может ограничить изменение самого Vec
```

---

## Перебор `Vec`

Чтение:

```rust
let v = vec![100, 32, 57];

for i in &v {
    println!("{i}");
}
```

Здесь элементы заимствуются через неизменяемые ссылки.

Изменение:

```rust
let mut v = vec![100, 32, 57];

for i in &mut v {
    *i += 50;
}
```

`i` имеет форму изменяемой ссылки, поэтому для изменения значения используется разыменование:

```rust
*i
```

Во время такого цикла нельзя одновременно вставлять или удалять элементы из самого вектора: цикл уже заимствует его. Язык программирования Rust(2)

---

## Разные типы в одном `Vec`

Напрямую:

```text
Vec<T>
→ один T
```

Но если набор возможных типов известен заранее, их можно объединить через `enum`:

```rust
enum SpreadsheetCell {
    Int(i32),
    Float(f64),
    Text(String),
}

let row = vec![
    SpreadsheetCell::Int(3),
    SpreadsheetCell::Text(String::from("blue")),
    SpreadsheetCell::Float(10.12),
];
```

Фактически все элементы имеют один тип:

```text
SpreadsheetCell
```

а разные данные находятся внутри его вариантов.

Затем варианты можно обрабатывать через `match`.

Это применение уже изученных:

```text
enum + match
```

для создания типобезопасной неоднородной коллекции с заранее известным набором вариантов. Язык программирования Rust(2)

---

## Уничтожение `Vec`

Когда вектор выходит из области видимости:

```rust
{
    let v = vec![1, 2, 3];
}
```

удаляется:

```text
сам Vec
+
его элементы
```

То есть обычные правила владения продолжают действовать и для коллекций. Язык программирования Rust(2)

---

# `String` и `&str`

## Два основных строковых типа

В ядре языка находится:

```text
str
```

обычно используемый в заимствованной форме:

```rust
&str
```

Стандартная библиотека предоставляет:

```rust
String
```

`String`:

```text
владеет данными
изменяем
может увеличиваться
UTF-8
```

`&str`:

```text
заимствованный строковый срез
UTF-8
```

Строковые литералы:

```rust
"hello"
```

имеют форму `&str`.

Книга описывает `String` как оболочку вокруг последовательности байтов с дополнительными гарантиями и операциями для работы с текстом. Язык программирования Rust(2)

---

## Создание `String`

Пустая:

```rust
let mut s = String::new();
```

Из `&str`:

```rust
let s = String::from("hello");
```

или:

```rust
let s = "hello".to_string();
```

В данном случае `String::from` и `to_string` дают эквивалентный результат. Язык программирования Rust(2)

---

## Добавление текста

### `push_str`

Добавляет строковый срез:

```rust
let mut s = String::from("foo");

s.push_str("bar");
```

Результат:

```text
foobar
```

`push_str` принимает `&str`, поэтому ему не нужно получать ownership передаваемой строки.

Например:

```rust
let mut s1 = String::from("foo");
let s2 = "bar";

s1.push_str(s2);

println!("{s2}");
```

`s2` остаётся доступной. Язык программирования Rust(2)

---

### `push`

Добавляет один `char`:

```rust
let mut s = String::from("lo");

s.push('l');
```

Результат:

```text
lol
```

Различие:

```text
push_str(&str)
→ добавить строковый срез

push(char)
→ добавить один char
```

---

# Объединение строк

## Оператор `+`

```rust
let s1 = String::from("Hello, ");
let s2 = String::from("world!");

let s3 = s1 + &s2;
```

После операции:

```text
s1 → больше недействителен
s2 → остаётся действителен
s3 → владеет результатом
```

Причина в приблизительной сигнатуре вызываемого механизма:

```rust
fn add(self, s: &str) -> String
```

Первый аргумент:

```text
self
→ передаётся ownership
```

Второй:

```text
&str
→ только заимствуется
```

Поэтому:

```rust
s1 + &s2
```

перемещает `s1`, но не `s2`.

Компилятор может привести:

```text
&String → &str
```

для второго аргумента. Язык программирования Rust(2)

---

## `format!`

При сложном объединении:

```rust
let s1 = String::from("tic");
let s2 = String::from("tac");
let s3 = String::from("toe");

let s = format!("{s1}-{s2}-{s3}");
```

получаем:

```text
tic-tac-toe
```

`format!`:

```text
возвращает String
+
использует ссылки на аргументы
+
не забирает их ownership
```

Поэтому для объединения нескольких значений он часто читается проще, чем цепочка `+`. Язык программирования Rust(2)

---

# Главное о UTF-8

## `String` — не массив символов

Это одна из центральных деталей главы.

Rust не разрешает:

```rust
let s = String::from("hello");

let c = s[0]; // ошибка
```

Причина: `String` хранится в UTF-8, где один воспринимаемый символ не обязан соответствовать одному байту. Язык программирования Rust(2)

Например, книга показывает:

```rust
"Hola"
```

имеет длину:

```text
4 байта
```

а:

```rust
"Здравствуйте"
```

занимает:

```text
24 байта
```

хотя визуально в слове 12 букв.

Следовательно:

```text
индекс 0
```

не может однозначно означать «первый символ».

---

## Три уровня представления текста

Книга выделяет три способа смотреть на UTF-8 строку:

```text
1. bytes
   ↓
   реальные u8 в памяти

2. Unicode scalar values
   ↓
   Rust char

3. grapheme clusters
   ↓
   то, что пользователь может воспринимать как буквы
```

Эти понятия не всегда совпадают.

Поэтому модель:

```text
1 byte
≠ обязательно 1 char
≠ обязательно 1 видимый символ
```

Язык программирования Rust(2)

---

## Почему `String[index]` запрещён

Есть две основные причины.

Первая:

```text
непонятно, что вернуть:

byte?
char?
grapheme?
```

Вторая — производительность.

Программист обычно ожидает от индексирования:

```text
O(1)
```

Но для определения некоторого Unicode-символа пришлось бы проходить строку и анализировать границы UTF-8.

Поэтому Rust требует явно указать, что именно нужно получить. Язык программирования Rust(2)

---

# Строковые срезы

Можно брать диапазон байтов:

```rust
let hello = "Здравствуйте";

let s = &hello[0..4];
```

В примере получается:

```text
"Зд"
```

потому что эти символы занимают по два байта.

Но:

```rust
&hello[0..1]
```

попадает внутрь многобайтового символа и вызывает `panic`.

Следовательно:

```text
строковый slice использует байтовые границы
```

и диапазон обязан проходить по корректным границам UTF-8. Язык программирования Rust(2)

Это один из главных подводных камней `String`.

---

## `chars()` и `bytes()`

Если нужны Unicode scalar values:

```rust
for c in "Зд".chars() {
    println!("{c}");
}
```

получаем значения типа:

```text
char
```

Если нужны реальные байты:

```rust
for b in "Зд".bytes() {
    println!("{b}");
}
```

получаем:

```text
208
151
208
180
```

То есть при работе со строкой лучше явно выбирать:

```text
нужны символы Unicode?
→ chars()

нужны байты?
→ bytes()
```

Стандартная библиотека не предоставляет непосредственного механизма разбиения на графемные кластеры; книга указывает, что для этого существуют отдельные библиотеки. Язык программирования Rust(2)

---

# `HashMap<K, V>`

`HashMap` хранит соответствия:

```text
key → value
```

Например:

```text
"Blue"   → 10
"Yellow" → 50
```

В отличие от `Vec`, где данные обычно ищутся по числовому индексу, `HashMap` позволяет получать значение по ключу.

Все ключи должны иметь один тип `K`, а значения — один тип `V`. Данные хранятся в куче. Язык программирования Rust(2)

---

## Создание

`HashMap` не входит в prelude, поэтому нужен импорт:

```rust
use std::collections::HashMap;
```

Создание:

```rust
let mut scores = HashMap::new();

scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Yellow"), 50);
```

Получаем тип вида:

```text
HashMap<String, i32>
```

---

## Чтение

```rust
let team = String::from("Blue");

let score = scores.get(&team);
```

`get` возвращает:

```text
Option<&V>
```

То есть:

```text
ключ найден
→ Some(&value)

ключа нет
→ None
```

В книге также используется:

```rust
scores.get(&team).copied().unwrap_or(0)
```

чтобы получить значение `i32`, а при отсутствии ключа использовать `0`. Язык программирования Rust(2)

---

## Перебор `HashMap`

```rust
for (key, value) in &scores {
    println!("{key}: {value}");
}
```

Важно:

```text
порядок обхода HashMap
не гарантируется как порядок вставки
```

В книге пары могут выводиться в произвольном порядке. Язык программирования Rust(2)

---

# `HashMap` и ownership

При вставке `Copy`-значений:

```rust
scores.insert(key, 10);
```

например `i32`, значение копируется.

Для владеющих типов:

```rust
let key = String::from("Favorite color");
let value = String::from("Blue");

map.insert(key, value);
```

оба `String` перемещаются в карту:

```text
key ─── move ───→ HashMap
value ─ move ───→ HashMap
```

После этого исходные переменные использовать нельзя.

Если же `HashMap` хранит ссылки, ownership данных не перемещается, но сами данные должны оставаться действительными достаточно долго. Язык программирования Rust(2)

---

# Обновление `HashMap`

## Перезапись

Если вставить значение с уже существующим ключом:

```rust
scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Blue"), 25);
```

получаем:

```text
"Blue" → 25
```

Новое значение заменяет старое. Язык программирования Rust(2)

---

## Вставить, только если ключа ещё нет

Для этого существует API:

```rust
entry(...)
```

Пример:

```rust
scores
    .entry(String::from("Yellow"))
    .or_insert(50);
```

Смысл:

```text
ключ есть
→ сохранить текущее значение

ключа нет
→ вставить 50
```

`or_insert` возвращает изменяемую ссылку на значение:

```text
&mut V
```

Язык программирования Rust(2)

---

## Изменить значение на основе старого

Это позволяет делать:

```rust
let text = "hello world wonderful world";
let mut map = HashMap::new();

for word in text.split_whitespace() {
    let count = map.entry(word).or_insert(0);
    *count += 1;
}
```

Механизм:

```text
entry(word)
    ↓
ключ есть?
 ┌──┴──┐
да    нет
│      │
value  вставить 0
 └──┬──┘
    ↓
&mut value
    ↓
*count += 1
```

Результат соответствует подсчёту количества появлений каждого слова. Язык программирования Rust(2)

Это один из наиболее полезных паттернов работы с `HashMap`.

---

# 3. Важные детали

## Коллекции не обходят borrowing

Для всех трёх типов продолжают работать прежние правила:

```text
ownership
borrowing
move
Copy
drop
```

Особенно важно для `Vec`:

```text
&v[index]
+
изменение размера v
→ потенциальная релокация памяти
→ Rust запрещает конфликт
```

Для `HashMap`:

```text
insert(String, String)
→ ownership может перейти карте
```

---

## `Vec<T>` содержит один тип

```text
Vec<i32>      ✓
Vec<String>   ✓
```

Для заранее известного набора различных форм данных:

```text
enum
+
Vec<Enum>
```

---

## У `String` длина связана с байтами

Не считать:

```text
len() = количество человеческих букв
```

В UTF-8 это неверно.

Модель:

```text
String
→ UTF-8 bytes
```

Поэтому нельзя использовать обычную числовую индексацию для получения символа.

---

## Строковый диапазон может `panic`

```rust
&s[a..b]
```

работает по байтовым позициям.

Если `a` или `b` разрезает UTF-8-символ:

```text
panic
```

Для обхода текста явно выбирай:

```rust
chars()
bytes()
```

---

## `+` меняет ownership

```rust
let s3 = s1 + &s2;
```

После:

```text
s1 invalid
s2 valid
s3 valid
```

Если не хочется передавать ownership исходных строк и комбинация сложная:

```rust
format!(...)
```

в книге показан как более читаемый вариант.

---

## `HashMap::get`

Возвращает:

```rust
Option<&V>
```

Это снова связывает коллекции с уже изученным `Option<T>`:

```text
получение данных может завершиться
"значение есть / значения нет"
```

---

## `entry`

Запомнить связку:

```rust
map.entry(key).or_insert(default)
```

Она нужна для двух типичных сценариев:

```text
вставить default,
если ключ отсутствует

или

получить &mut V
и обновить существующее значение
```

---

## Хеширование

Книга указывает, что используемая `HashMap` хеш-функция по умолчанию выбирается с учётом защиты от определённого класса DoS-атак, что является компромиссом с производительностью. Если профилирование покажет, что хеширование является узким местом, механизм hasher можно заменить. Язык программирования Rust(2)

Для базового владения Rust этого достаточно; детали `BuildHasher` здесь запоминать не нужно.

---

# 4. Что запомнить

Главная схема:

```text
Vec<T>
→ список
→ один тип T
→ переменный размер

String
→ владеющий UTF-8 текст
→ изменяемый
→ не поддерживает String[index]

HashMap<K, V>
→ key → value
→ один тип ключей K
→ один тип значений V
```

Минимум по `Vec`:

```rust
let mut v = vec![1, 2, 3];

v.push(4);

let a = &v[0];
let b = v.get(0);
```

Разница:

```text
&v[index]
→ &T
→ invalid index = panic

v.get(index)
→ Option<&T>
→ invalid index = None
```

Перебор:

```rust
for x in &v {
    ...
}

for x in &mut v {
    *x += 1;
}
```

---

Минимум по строкам:

```text
String
→ owned

&str
→ borrowed
```

Создание:

```rust
String::new()
String::from("text")
"text".to_string()
```

Добавление:

```rust
s.push_str("text");
s.push('x');
```

Объединение:

```rust
let c = a + &b;
```

помнить:

```text
a moved
b borrowed
```

или:

```rust
let c = format!("{a}{b}");
```

---

Главное правило строк:

```text
String ≠ массив char
```

Внутренняя модель:

```text
UTF-8 bytes
     ↓
Unicode scalar values
     ↓
grapheme clusters
```

Они не обязаны соответствовать друг другу один к одному.

Поэтому:

```rust
string[0]
```

не работает.

Использовать:

```rust
string.chars()
string.bytes()
```

либо осторожно:

```rust
&string[a..b]
```

только по корректным UTF-8-границам.

---

Минимум по `HashMap`:

```rust
use std::collections::HashMap;

let mut map = HashMap::new();

map.insert(key, value);

let result = map.get(&key);
```

`get`:

```text
Option<&V>
```

Обновление:

```rust
map.insert(key, new_value);
```

→ перезаписать.

```rust
map.entry(key).or_insert(default);
```

→ вставить только при отсутствии.

Типичный счётчик:

```rust
let count = map.entry(key).or_insert(0);
*count += 1;
```

---

Самая важная связь всей главы:

```text
COLLECTIONS
     ↓
хранят много данных
     ↓
но ownership никуда не исчезает

Vec
→ ссылки на элементы связаны с самим Vec

String
→ операции могут заимствовать или перемещать ownership

HashMap
→ вставленные String могут стать собственностью карты
```

И ещё одна модель, которую стоит удержать:

```text
Vec<T>        → доступ по позиции
HashMap<K,V>  → доступ по ключу
String        → UTF-8 текст, а не индексируемый массив символов
```

**Объём конспекта:** примерно **10–12 тыс. символов** с кодом.

**Время переноса в тетрадь:** примерно **55–70 минут**. При сокращении первым можно убрать второстепенные примеры, но стоит оставить `Vec::get`, конфликт `push` со ссылкой на элемент, модель UTF-8, `String + &str` и `HashMap::entry().or_insert()`.
